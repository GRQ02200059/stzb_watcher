# 战场监控悬浮窗设计

## 目标

为战场监控增加可选的系统级透明悬浮窗。用户切换到率土之滨或其他 App 后，仍可查看全部已发现队伍的精简状态。

每条队伍仅展示：

- 玩家名称。
- 三名武将的文字名称与红度。
- 当前状态（行军、驻守、驻扎/要塞、调动及其他仍存在状态）。
- 目的地。
- 行军队伍的到达时间；非行军状态展示最后更新时间。
- 已记录历史胜率；没有匹配战报时展示“胜率 --”。

## 队伍保留与排序

悬浮服务从现有 `BattlefieldRepository` 获取 5026/5028 解析结果，不建立第二套协议解析逻辑。

- 使用 `teamId` 作为唯一键。
- 同队新状态覆盖旧状态，并移动到列表顶部。
- 新发现队伍插入顶部。
- 队伍从后续 5028 快照消失时不删除，保留其最后状态。
- 列表按最后更新时间倒序排列，全部队伍可上下滚动。
- 悬浮服务生命周期内持续保留；用户停止悬浮服务后，下一次启动从当前仓库快照重新开始积累。

为避免解析 UI 文案，领域展示模型补充结构化的 `teamId`、目的地、到达时间和可空历史胜率字段。胜率来自现有 `Local13A2TeamInsight.stats`。

## 系统架构

新增 `BattlefieldOverlayService` 前台服务：

- 通过 `WindowManager` 创建 `TYPE_APPLICATION_OVERLAY` 窗口。
- 使用 ComposeView 渲染悬浮内容，并设置独立 Lifecycle/SavedState owners。
- 服务复用应用单例 `BattlefieldRepository`，每 2 秒执行刷新并收集快照。
- 服务维护 `LinkedHashMap<teamId, OverlayTeam>`，实现覆盖、置顶和不删除。
- 常驻低优先级通知显示“战场悬浮监控运行中”，提供停止操作；Android 14+ 使用 `specialUse` 前台服务类型。

应用 Manifest 增加 `SYSTEM_ALERT_WINDOW` 权限以及不导出的悬浮前台服务声明。

## 界面与交互

战场页面标题区增加“悬浮监控”开关/按钮：

1. 首次开启时若没有悬浮窗权限，跳转系统 `ACTION_MANAGE_OVERLAY_PERMISSION` 页面。
2. 返回应用后若权限已授予，启动悬浮前台服务。
3. 已运行时点击可停止悬浮服务。
4. 权限被拒绝时保持关闭并显示说明。

展开态：

- 深色半透明圆角面板，顶部显示“战场队伍”、总数、折叠按钮。
- 顶部区域可拖动整个悬浮窗。
- 队伍列表可滚动，每条三行紧凑文字；状态与胜率位于首行右侧。
- 面板高度限制在屏幕可用高度内，宽度适合游戏竖屏覆盖且不铺满全屏。

折叠态：

- 显示半透明浮球，“战场”和当前累计队伍数。
- 浮球可拖动，点击恢复展开。
- 展开/折叠位置以及透明度在同一次服务运行期间保持。

悬浮窗本身提供关闭按钮，等同于停止服务。窗口不抢输入焦点；只有拖动、滚动、折叠和关闭区域接收触摸。

## 状态与异常

- 没有数据时展示“等待战场队伍数据”。
- 抓包停止时保留当前队伍，并在标题显示“数据暂停”。
- 仓库刷新失败时保留已有列表，通知/面板展示最近一次错误，不退出服务。
- 系统回收服务后不自动重启，避免未经用户确认持续悬浮。
- 权限运行中被撤销时安全移除窗口并停止服务。

## 测试与验收

- 纯状态测试覆盖：新增置顶、同队覆盖置顶、快照消失不删除、不同状态保留、胜率可空。
- 领域映射测试覆盖目的地、到达时间、武将红度和胜率。
- Compose 测试覆盖展开列表、折叠浮球、空态和控制按钮。
- 战场页面测试覆盖开启入口及权限被拒绝反馈。
- 完整单元测试、AndroidTest 编译和 APK 构建通过后覆盖安装。
- 真机验收悬浮权限、跨 App 展示、拖动、滚动、折叠、关闭、通知停止和列表最新置顶。

## 约束

- 不显示头像、等级、战法、兵力和完整战报卡片。
- 不删除数据库或现有战场历史。
- 不修改 5026/5028 的底层解析协议。
- 保留用户修改的根目录 `README.md` 和未跟踪的 `astzb/third_party`。
