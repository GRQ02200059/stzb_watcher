技术架构

本地优先，双链路同源

STZB Watcher 采用本地优先数据策略：Web 与 Android 两条独立采集链路各自完成抓包、解析与本地入库， 再由同一套 Kotlin 战斗引擎提供共享战斗语义，保证两端模拟结果一致。数据默认留在本机， 闭环之内，尽在掌控。

01数据流架构

两条横向数据链路 + 中枢共享战斗引擎，构成完整的本地数据闭环。窄屏可横向滚动查看全图。

03数据与隐私 · 本地优先

数据默认留在本机，账号与抓包文件不入 Git，对外部署时以令牌收口访问。

业务数据存本地 SQLite

Web 原始数据默认写入 capture_new/，业务数据落本地 SQLite；Android 数据存 App 私有目录本地 SQLite，并支持本机导出。

敏感文件不提交 Git

数据库、账号文件、日志与抓包文件一律不入 Git，避免个人战场数据外泄到代码仓库。

档案文件含本机信息

current_profile.json 与 profiles.json 可能包含角色、区服与本机路径，仅存于本地、不外传。

对外部署设访问令牌

对外或局域网部署 Web 服务时，应设置 STZB_API_TOKEN 收口接口访问，防止未授权拉取数据。

Android 抓包六阶段闭环

抓包链路需依次通过六个阶段，形成从启动到停止恢复的完整闭环。

01 Native 组件 NDK 就绪
02 VPN 通道 VpnService
03 SOCKS 连接 代理建立
04 已知协议 协议识别
05 本地入库 Local SQLite
06 停止与恢复 网络还原
