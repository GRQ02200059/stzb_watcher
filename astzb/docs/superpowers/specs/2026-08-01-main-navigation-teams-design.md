# 主导航与队伍/团队页面重构设计

## 目标

将 Android Compose 主界面从“战场 / 战报 / 同盟 / 更多”调整为“战场 / 队伍 / 团队 / 更多”，使四个一级入口对应最常使用的业务，而不是旧模块名称或过渡页面。

## 一级导航

底部导航固定为：

1. 战场：保留现有实时战场监控。
2. 队伍：展示从全服玩家战报聚合得到的玩家队伍。
3. 团队：直接展示团队报表。
4. 更多：承载战报、排行榜、同盟成员、地图、公告、抓包控制及其他工具。

原有数据和页面不删除，只调整入口与默认内容。

## 队伍页面

### 数据来源

- 使用 `LocalStzbRepository.loadPlayerBattleTeams(0)`。
- 每条记录包含玩家、同盟、攻守方、武将 ID/名称、战法、出场次数、胜场与胜率。
- 武将头像继续使用 `HeroNameResolver.iconIdOf()` 和现有 Compose 头像加载组件。

### 页面结构

- 顶部标题为“全服玩家队伍”，底部导航简称“队伍”。
- 顶部显示队伍总数、玩家数和平均胜率等概览。
- 提供玩家/同盟/武将或战法的文本搜索，以及攻方/守方筛选。
- 队伍按出场次数降序、胜率降序排列。
- 每支队伍使用紧凑三将头像卡：三列展示武将头像和名称；队伍数据没有等级/进阶时不伪造数值。
- 战法以紧凑标签展示；战报聚合只能提供队伍级战法集合时，在卡片底部显示集合，不强行绑定到某个武将。
- 卡片顶部显示玩家、同盟和攻守方，底部显示场次、胜场和胜率。
- 无数据时明确提示需要先采集完整玩家战报。

### 交互

- 搜索和攻守筛选只影响当前列表，不重新读取数据库。
- 下拉刷新或刷新按钮重新读取数据库。
- 卡片保持可点击扩展能力，但本次不新增详情页。

## 团队页面

### 数据来源

- 复用 `RankingRepository.loadTeamReport()` 与现有团队报表模型。
- 不把排行榜作为团队页的默认或并列一级内容。

### 页面结构

- 页面标题为“团队报表”，底部导航简称“团队”。
- 默认显示团队维度、全部时间。
- 保留团队/成员维度、今日/本周/全部周期及分组筛选。
- 展示人数、战报、胜负平、胜率、攻城、功勋和势力等现有字段。

## 更多页面

- 保留现有抓包控制、旧控制台、地图和公告入口。
- 新增或迁入：
  - 战报；
  - 排行榜；
  - 同盟成员；
  - 现有其他工具入口。
- 所有二级页面提供明确返回入口。
- 排行榜二级页默认进入排行榜，团队页不受其页面状态影响。

## 导航与状态

- 一级 route 使用业务含义命名为 `battlefield / teams / team-report / more`。
- 旧 `battles`、`alliance` 功能改为更多中的二级 route，避免与新一级页面语义混淆。
- 各一级页面 ViewModel 独立保存加载、筛选和错误状态。
- 切换底部导航时使用现有 `saveState/restoreState` 行为。

## 组件边界

- `TeamsRepository`：读取并映射全服玩家队伍。
- `TeamsViewModel`：负责刷新和本地筛选。
- `TeamsScreen`：页面骨架、概览、筛选和列表。
- `PlayerTeamCard`：三将头像与队伍统计。
- `TeamReportScreen`：复用现有报表内容，但移除排行榜页签依赖。
- `LegacyToolsScreen`：只负责更多入口布局和二级导航回调。

## 验收标准

1. 底部导航显示且只显示“战场 / 队伍 / 团队 / 更多”。
2. 点击“队伍”直接看到真实全服玩家队伍三将头像卡，不出现旧战报列表。
3. 队伍卡显示玩家、同盟、攻守方、三将头像、队伍战法、场次和胜率；缺失等级时不显示虚假等级。
4. 点击“团队”直接看到团队报表和其维度/周期/分组筛选，不先进入同盟成员或排行榜。
5. 战报、排行榜、同盟成员、地图、公告和抓包工具都能从“更多”进入并返回。
6. 原有战场页与三将监控卡不回归。
7. 单元测试覆盖队伍映射和筛选；Compose 测试覆盖四个导航标签、队伍卡、团队默认页与更多入口。
8. 完整单测、AndroidTest 编译、Debug 构建通过，并在设备覆盖安装后逐个验证四个主入口。
