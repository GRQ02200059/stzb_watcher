# 全站现代化质感与交互特效系统设计

日期：2026-08-15

## 1. 目标

在不改变现有业务结构、数据逻辑、Vanilla JS 架构和 `208px` 桌面侧栏的前提下，统一升级 12 个主导航页面的视觉质感与交互反馈。

本轮不是重新设计页面信息架构，也不是增加持续播放的装饰动画，而是建立一套全站共享的现代化材质、状态和事件反馈系统：

- 常态使用精细微交互与克制的空间玻璃层；
- 强特效只由真实业务事件触发；
- 所有页面共享统一组件和状态语言；
- 保持高信息密度、清晰度和长时间使用舒适度；
- 在低性能设备和 `prefers-reduced-motion` 下完整降级。

### 2.2 不在本轮范围

- 不新增业务页面或主导航入口；
- 不调整 12 个页面的业务字段、API 和计算口径；
- 不引入 React、Vue 或其他前端框架；
- 不实现常驻粒子、无限高亮、全屏闪烁或持续扫描；
- 不改变隐藏兼容页面的业务行为；
- 不实现主动游戏操作、发包或自动化控制；
- 不重写现有 Canvas 地图和 Kotlin 模拟器；
- 不恢复已经从产品界面移除的协议研究入口。

## 3. 设计方向

采用方案 A：“全局动效与材质系统优先”。

系统由三层组成：

1. **基础材质层**：全站共享的表面、边线、高光、阴影、交互与状态组件；
2. **视觉域主题层**：五个业务域只改变强调色、环境光和少量纹理；
3. **事件特效层**：真实业务事件通过统一 HUD API 触发一次性反馈。

业务页面不自行定义新的玻璃材质、关键帧和强特效。页面只声明视觉域、组件语义和事件类型。

## 4. 基础材质系统

### 4.1 五级 Surface

新增五级语义表面，不允许业务页面直接使用散落的十六进制背景色：

| Token | 用途 | 材质 |
|---|---|---|
| `--surface-canvas` | 页面画布 | 最深实体背景，允许极弱环境光 |
| `--surface-panel` | 普通业务面板 | 实体表面，清晰边线，无模糊 |
| `--surface-raised` | 可交互卡片、选中项 | 轻微抬升、内高光和短阴影 |
| `--surface-overlay` | Sticky Header、工具条、抽屉 | 半透明玻璃、有限背景模糊 |
| `--surface-modal` | Dialog、命令面板 | 最强空间层级、遮罩和焦点隔离 |

### 4.2 玻璃使用边界

允许使用玻璃材质的位置：

- 固定侧栏；
- Sticky Header；
- 浮动工具条；
- 抽屉；
- Dialog 与命令面板；
- 地图上的悬浮情报卡。

禁止在以下位置批量使用背景模糊：

- 长表格的每一行；
- KPI 卡片集合；
- 大量重复列表卡片；
- Canvas 地图本体；
- 页面画布的全部区域。

同一视口内允许存在的活动模糊层不超过 4 个。

### 4.3 边线、阴影与环境光

- 普通面板使用 1px 低对比边线；
- Raised 表面增加顶部内高光；
- Overlay 和 Modal 使用更长但透明度更低的阴影；
- 环境色光只出现在页面顶部、选中区域和真实事件附近；
- 禁止所有卡片同时发光；
- 阴影不得替代明确边界，低对比显示器上仍需可辨识。

### 4.4 圆角

统一使用现有语义半径体系：

- 控件：4–6px；
- 普通卡片：8–10px；
- 大面板：10–12px；
- Overlay 和 Dialog：12–16px。

不使用胶囊形大卡片；胶囊仅用于状态、筛选和短标签。

## 5. 五视觉域主题

五个视觉域保持同一组件结构，仅通过域 token 调整强调色和事件语言。

### 5.1 Intelligence

- 主色：青色到天蓝；
- 环境效果：极弱网格、雷达和扫描语义；
- 事件效果：目标锁定、风险边线、地图标记脉冲；
- 页面：州郡分布、战场情报、实时部队。

### 5.2 Operations

- 主色：橙色到红色；
- 环境效果：执行状态、进度和完成反馈；
- 事件效果：模拟完成、任务阶段推进、失败阻断；
- 页面：打城考勤、战斗模拟。

### 5.3 Organization

- 主色：蓝色到紫色；
- 环境效果：身份、分组和关系层级；
- 事件效果：成员状态变化、分组更新、排名变化；
- 页面：玩家队伍、同盟成员队伍、团数据。

### 5.4 Analysis

- 主色：靛青到青蓝；
- 环境效果：数据聚焦、证据分类和对比；
- 事件效果：积分重算、阵容切换、模拟证据到达；
- 页面：自定义积分、武将阵容、阵容战法研究。

### 5.5 System

- 主色：中性蓝灰；
- 环境效果：低干扰、强调可读性；
- 事件效果：设置保存、连接恢复、运行链异常；
- 页面：设置中心。

## 6. 统一微交互

### 6.1 时长与缓动

| 类型 | 时长 |
|---|---:|
| Hover / focus | 120–180ms |
| Pressed | 80–120ms |
| 卡片选中 | 160–220ms |
| 抽屉 / 菜单 | 180–240ms |
| Dialog | 200–260ms |
| 数字变化 | 180–320ms |
| 真实事件演出 | 800–2400ms |

统一使用无弹簧过冲的缓动。业务页面不得定义超过 400ms 的普通控件动画。

### 6.2 按钮

- Hover：边线和文字亮度增加，不放大；
- Pressed：`scale(0.98)`；
- Focus-visible：2px 可见焦点环；
- Loading：保留按钮宽度，显示局部进度；
- Disabled：不仅降低透明度，同时取消阴影和指针反馈；
- Primary 按钮不使用持续辉光。

### 6.3 卡片与列表

- 可点击卡片 Hover 最多上移 2px；
- 选中卡片使用域色边线、左侧标记或顶部内高光；
- 新增或更新行短暂显示变化边线，不重播整张列表动画；
- 大表格行不做位移动画；
- 排名变化允许使用一次性方向标记和数字过渡。

### 6.4 输入与筛选

- Focus 使用域色边线和弱外环；
- 清空、搜索和筛选变化有明确局部 refreshing 状态；
- 输入错误使用文字、图标和边线共同表达，不只依赖红色；
- Select 和日期控件保持原生键盘行为。

### 6.5 抽屉与 Dialog

- 使用 opacity 与 8px 以内位移；
- 背景遮罩渐入；
- 打开后焦点进入浮层，关闭后返回触发按钮；
- Escape 可关闭非阻断浮层；
- 移动端 Dialog 不超出视口，内部可滚动；
- 不使用缩放过冲或 3D 翻转。

## 7. 页面状态系统

`dashboard-hud.mjs` 的状态模型扩展为：

```text
idle
loading
refreshing
success
empty
stale
warning
error
```

### 7.1 Loading

- 首次加载显示结构匹配的 Skeleton；
- Skeleton 只运行一次柔和明暗过渡；
- 不用旋转图标占据整页。

### 7.2 Refreshing

- 已有数据继续可见；
- 目标面板顶部或底部显示 2px 进度边线；
- 禁止清空已有内容后重新显示 Skeleton。

### 7.3 Empty

- 说明为什么为空；
- 提供明确下一步，例如放宽筛选、刷新或选择对象；
- 空状态不使用大型插画。

### 7.4 Stale

- 显示数据时间和陈旧程度；
- 面板边线和状态标签进入 warning；
- 不把 stale 数据伪装为实时状态。

### 7.5 Error

- 区分网络、后端不可用、权限、数据格式和业务错误；
- 保留上一次成功内容时，错误以非阻断方式显示；
- 提供重试动作，但避免自动高频重试。

## 8. 事件特效系统

### 8.1 统一接口

扩展 `static/dashboard-hud.mjs`，提供小型事件接口：

```javascript
window.HudSystem.emit({
  type,
  target,
  domain,
  severity,
  value,
  message,
  timestamp,
});
```

允许的第一批事件类型：

```text
intelligence:risk-detected
battle:report-arrived
simulation:completed
score:recalculated
connection:restored
data:stale
operation:stage-changed
```

HUD 深模块负责：

- 事件去重；
- 动效等级判断；
- 目标元素定位；
- 一次性 CSS class 生命周期；
- Toast；
- 数字变化；
- reduced-motion 降级；
- 页面不可见时不播放动画。

业务模块只发送语义事件，不操作关键帧或定时器。

### 8.2 高风险情报

- 地图目标显示一次准星收束；
- 对应风险卡显示红色边缘脉冲；
- 持续时间不超过 2.4 秒；
- 不自动改变地图缩放或用户选中对象；
- 相同 WID 和风险等级在冷却时间内不重复播放。

### 8.3 新战报

- 新战报所在行短暂高亮；
- KPI 数字平滑更新；
- 页面不在前台时仅记录状态，回到前台不补播强动画；
- 多条战报批量到达时合并为一次反馈。

### 8.4 模拟完成

- 结果面板播放一次局部扫描；
- 成功状态脉冲；
- 胜率和次数使用数字过渡；
- 存在未支持效果时使用 warning，而非纯 success。

### 8.5 积分重算

- 排名与分值变化使用方向和数字过渡；
- 只对变化行播放；
- 写入确认前的预览不触发完成演出。

### 8.6 连接恢复

- Header 连接状态从 stale/error 过渡到 live；
- 显示一次低优先级 Toast；
- 不播放全屏效果。

## 9. Toast 系统

统一四类 Toast：

| 类型 | 用途 |
|---|---|
| info | 普通刷新和导航反馈 |
| success | 模拟完成、设置保存、连接恢复 |
| warning | 数据陈旧、证据不完整、部分效果未支持 |
| critical | 高风险情报、写操作失败、关键链路故障 |

Toast 必须包含：

- 简短标题；
- 可选的来源；
- 时间；
- 可选动作；
- 屏幕阅读器 live region：`critical` 和错误使用 `aria-live="assertive"`，其余类型使用 `aria-live="polite"`。

同类型重复 Toast 在短时间内合并计数。关键 Toast 不自动无限堆叠。

## 10. 12 页面适配要求

### 10.1 玩家队伍

- 队伍卡和成员身份层级使用 organization 域；
- 搜索与筛选采用局部 refreshing；
- 选中队伍使用边线和关系色，不移动整表。

### 10.2 自定义积分

- KPI、榜单和规则控制台使用 analysis 域；
- 重算仅高亮变化行；
- Dialog 使用 Modal Surface；
- 排名变化同时展示方向与数值。

### 10.3 打城考勤

- 四阶段条使用 operations 域；
- 当前阶段有轻微进度反馈；
- 阶段改变事件只播放一次；
- 不让所有任务行持续发光。

### 10.4 同盟成员队伍

- 组织、分组和成员身份层级更清晰；
- 可点击行统一 Hover、Pressed 和 Focus；
- 空阵容与数据缺失使用明确状态。

### 10.5 武将阵容

- 排名前三不使用 Emoji；
- 阵容卡强化证据与样本层级；
- 排名或筛选变化使用局部过渡。

### 10.6 团数据

- KPI 与表格使用 organization 域；
- 分组切换保持已加载内容直到新结果到达；
- 导出按钮使用统一 loading 状态。

### 10.7 战斗模拟

- 保留现有全息画像设计；
- 抽屉、Dialog、结果面板接入统一 Surface；
- 模拟完成通过 HUD 事件触发；
- 未支持效果显示 warning 状态。

### 10.8 州郡分布

- 图表、KPI 和组织分布使用 intelligence 域；
- 图表更新只过渡数据，不让整个面板闪烁；
- 无数据和陈旧数据明确区分。

### 10.9 设置中心

- 使用 system 域；
- 动效强度、密度和运行健康状态层级清晰；
- 设置保存使用低优先级 success；
- 不使用扫描或强环境光。

### 10.10 战场情报

- 地图、雷达、详情抽屉统一玻璃浮层；
- 高风险事件支持准星收束；
- 地图本体不使用 backdrop-filter；
- 选中 WID 与风险状态可区分；
- 缩放和拖动期间暂停非必要动画。

### 10.11 阵容战法研究

- 三栏工作台强化空间层级；
- 模式、证据类型和选中槽位使用一致选中语言；
- 模拟完成接入统一事件反馈；
- 配置链和模拟链保持证据边界。

### 10.12 实时部队

- 部队列表、地图和证据面板使用 intelligence 域；
- 新部队、最近离线、stale 和 unknown 使用不同状态；
- 倒计时更新不触发整卡动画；
- 高风险部队事件可联动地图标记。

## 11. 动效等级

保留现有三档动效设置：

### Full

- 启用微交互；
- 启用有限玻璃环境光；
- 启用真实事件演出；
- 启用数字插值。

### Standard

- 默认档；
- 启用微交互和关键玻璃层；
- 缩短事件演出；
- 禁用非必要环境漂移。

### Reduced

- 禁用扫描、准星收束、位移、缩放和数字插值；
- 禁用持续 Skeleton 明暗过渡；
- 保留颜色、边线、状态文字和即时结果；
- 系统 `prefers-reduced-motion` 始终优先于应用设置。

## 12. 性能预算

- 普通动画仅允许 `transform` 和 `opacity`；
- 边线和颜色变化必须避免大面积重绘；
- 同一时刻活动动画元素不超过 6 个；
- 同一视口内活动 backdrop-filter 层不超过 4 个；
- Canvas 交互期间不运行动画 DOM 覆盖层；
- 页面隐藏时暂停非必要 ticker 和动画；
- 事件队列必须合并重复事件；
- 不新增常驻 `requestAnimationFrame` 循环；
- 不引入新的外部 CDN 或大型动画依赖；
- 375px–1920px 下不得引入页面级横向滚动。

## 13. 无障碍

- 所有交互状态必须支持键盘；
- Focus-visible 始终清晰；
- 状态不能只依赖颜色；
- Toast 使用适当的 `aria-live`；
- Dialog 焦点被正确约束和恢复；
- 玻璃表面必须达到文本对比度要求；
- 浏览器 200% 缩放时主要操作可完成；
- reduced-motion 下功能与信息完整；
- 页面保持单一 `<main>` landmark。

## 14. 架构与文件边界

### 14.1 深模块

`static/dashboard-hud.mjs` 继续作为唯一 HUD 行为深模块，负责：

- 域主题；
- 动效等级；
- 统一状态；
- 事件反馈；
- Toast；
- 数字变化；
- 动画生命周期。

### 14.2 样式层

优先扩展：

```text
static/dashboard-design-system.css
static/analysis-hud.css
static/intelligence-center.css
static/live-army-command.css
static/operations-hud.css
static/organization-hud.css
static/score-center.css
static/simulator-workbench.css
static/intelligence-research.css
```

`dashboard-design-system.css` 拥有全局 Surface、交互和状态组件。域 CSS 只添加域语义，不重新定义全局 token。

### 14.3 业务模块

业务 JS 只允许：

- 设置语义状态；
- 发送 HUD 事件；
- 标记发生变化的目标；
- 调用统一 loading / refreshing / empty / error 接口。

禁止业务模块：

- 新建全局动画 ticker；
- 自行定义重复 Toast；
- 直接操作 HUD 强特效 class；
- 复制动效降级判断。

## 15. 错误处理

- HUD 事件目标不存在时静默降级为 Toast，不抛出页面错误；
- 非法事件类型记录开发诊断，但不影响业务；
- 动画执行失败不影响数据渲染；
- 不支持 backdrop-filter 时回退到实体表面和更强边线；
- 页面切换后清理上一页面未完成的一次性 class；
- 请求失败保留最后成功内容时，不播放成功或完成动画。

## 17. 验收标准

1. 12 个页面共享统一现代材质与交互语言；
2. 五视觉域差异清晰但组件结构一致；
3. 普通业务卡片不滥用玻璃和辉光；
4. 强特效只由真实业务事件触发；
5. 所有请求状态具有 loading、refreshing、empty、stale 和 error 表达；
6. reduced-motion 下信息和操作完整；
7. 375、768、1024、1440、1920px 下无页面级横向滚动；
8. 200% 缩放时主要操作可完成；
9. 不新增常驻动画循环和外部动画依赖；
10. 不改变 API、业务口径和现有导航结构；
11. Node、Python 和 Chrome E2E 全量通过；
12. `git diff --check` 通过。
