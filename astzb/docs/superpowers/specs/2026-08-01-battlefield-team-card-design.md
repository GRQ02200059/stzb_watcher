# 战场紧凑三将卡设计

## 目标

把 Compose 战场页当前以多行文字展示的已记录队伍，改为接近网页端的信息卡：一眼看到三名武将头像、位置、等级、进阶和战法，同时保留行军、士气和历史战绩信息。

## 范围

- 仅调整 Compose 战场页的行军队伍卡片。
- 复用现有战报关联结果，不改变 5026/5028 解析或队伍匹配规则。
- 复用现有网易武将卡图地址和 `HeroNameResolver.iconIdOf()` 映射。
- 不修改旧版 `DashboardActivity` 页面。

## 卡片结构

### 顶部摘要

- 第一行：玩家名、同盟名、事件时间。
- 第二行：起点到目标路线、士气、当前行动状态。
- 使用当前优先级颜色作为细边框或状态色，不使用大面积高饱和背景。

### 三将阵容

- 已匹配历史阵容时，横向等宽显示三列。
- 位置顺序固定为大营、中军、前锋，对应现有阵容 `pos` 排序后的 1、2、3 号位。
- 每列包括：
  - 位置标签；
  - 1:1 紧凑方形头像；
  - 单行武将名；
  - `Lv.x · 进阶x`；
  - 最多三个战法标签，超长名称单行截断。
- 少于三名武将时只显示已有武将，剩余列不制造虚假占位。

### 底部信息

- 显示历史战绩、胜率、到达时间。
- 驻地、Buff、战斗效果等低频信息保留为紧凑辅助文字。
- 队伍 ID 不作为主视觉，仅在无匹配阵容或点击详情时用于诊断。

## 头像加载

- URL：`https://g0.gph.netease.com/ngsocial/community/stzb/cn/cards/cut/card_medium_{iconId}.jpg?gameid=g10`。
- `iconId` 来自 `HeroNameResolver.iconIdOf(heroId)`。
- Compose 使用应用内共享的异步加载器或新增轻量 Compose 包装，避免每次重组重复请求。
- 加载中显示低对比度骨架背景。
- 加载失败或 `heroId` 无效时显示武将名首字的渐变/主题色占位，不显示破图。

## 数据模型

- 为 `BattlefieldEvent` 增加只面向展示的队伍阵容数据：武将 ID、名称、位置、等级、进阶、战法。
- `BattlefieldEventMapper` 从 `Local13A2TeamInsight.lineup` 生成该数据。
- 非行军事件及未匹配队伍保持空阵容，继续使用现有通用事件卡布局。
- 不从格式化的 `details` 文本反向解析阵容，避免 UI 与中文文案耦合。

## 组件边界

- `BattlefieldEventCard`：选择通用卡或队伍卡布局。
- `BattlefieldTeamCard`：负责顶部摘要、三将横排和底部战绩。
- `BattlefieldHeroTile`：负责单名武将头像、资料和战法标签。
- 头像加载封装：负责 URL、缓存、加载态和失败态。

## 可访问性与适配

- 整张卡保持可点击，最小触控高度不低于 48dp。
- 头像提供包含位置和武将名的内容描述。
- 文本遵循系统字号；窄屏时三列仍等宽，名称与战法截断，不改为横向滚动。
- 明暗主题均使用 Material 颜色体系，保证文字和标签对比度。

## 验收标准

1. 已记录队伍显示三列紧凑武将头像卡，并能看到位置、姓名、等级、进阶和最多三个战法。
2. 同屏可辨认多支队伍，卡片不再由大段重复详情文字主导。
3. 无网络、头像 404 或未知武将时有稳定文字占位，页面不崩溃。
4. 未匹配历史阵容的行军仍正常显示玩家、路线、士气和诊断提示。
5. 战斗、攻城等非行军事件外观和行为不回归。
6. Compose UI 测试覆盖三将布局、无头像占位和无阵容回退；单元测试覆盖阵容展示模型映射。
7. Debug 构建、单元测试、AndroidTest 编译通过，并在连接设备上覆盖安装后验证真实队伍卡。
