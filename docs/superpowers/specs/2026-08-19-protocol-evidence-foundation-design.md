# 协议证据基础层设计

## 目标

为 stzb_watcher 建立可追溯、可测试、可持续扩展的协议证据基础层，作为后续战场、
同盟积分、战报赛季和 Web/Android 产品化的共同数据底座。

第一阶段不要求把所有命令立即转成业务功能，而是确保每个字段结论都能回答：命令号
及正式名称、真实抓包来源、客户端读取位置、Web/Android 当前处理方式、证据强度和
适用版本。

## 输入范围

真实样例来自仓库根目录 capture_new。当前发现 94 个八位十六进制命令目录。扫描器
不得修改、移动或重新编码这些用户数据。

客户端真值来自本机客户端 9.2.2 反编译目录，主要证据包括：

- Game.Network/Tenth.Network/NetCommandDef.cs 的命令定义；
- 命令请求、接收回调和数据模型类的字段读取；
- Game.Map 中的 WID 和 5026/5028 世界场景实现；
- Game.Data 中的表字段和服务端同步模型；
- /Users/bytedance/stzb/docs/protocol 中的已核验协议说明；
- /Users/bytedance/stzb/tools/monitor-agent/captures 中的官方抓包。

绝对路径只用于本地生成证据，版本化产物不得依赖本机路径。

当前实现的审计入口包括 scrapy_v2.py、realtime_writer.py、api_server.py、Android
本地解析器和 score_center。

## 证据等级

| 等级 | 含义 | 可否进入业务统计 |
|---|---|---|
| CLIENT_CONFIRMED | 客户端源码明确读取并可命名 | 可以 |
| CAPTURE_CONFIRMED | 多个样例位置和类型稳定，但客户端未命名 | 只能作为原始技术字段 |
| IMPLEMENTATION_ASSUMED | 只有项目旧实现或注释支持 | 不可以 |
| UNKNOWN | 只知道命令存在 | 不可以 |

业务层不得消费 IMPLEMENTATION_ASSUMED 或 UNKNOWN 字段。

## 版本化产物

### 命令目录

生成 data/protocol/client-9.2.2/command-catalog.json。每条命令至少记录：

- 八位十六进制 ID 和十进制 ID；
- 客户端正式命令名；
- 样例数量、decode kind 和仓库相对样例路径；
- 根类型、数组长度和结构漂移；
- 客户端源码锚点；
- Web 与 Android 的 typed/raw/unsupported 状态；
- 证据等级。

样例路径只保存仓库相对路径，不复制用户抓包进入版本控制。

### 字段注册表

生成 data/protocol/client-9.2.2/field-registry.json。字段记录包括：命令号、JSON path
或数组槽位、原始类型、空值规则、规范化名称、单位、时间语义、客户端源码、样例覆盖、
证据等级及双端投影位置。

原始值和规范化值必须分离，例如 rawHeroId=130497，normalizedHeroId=100497。

### 覆盖报告

生成 docs/verification/protocol-coverage-client-9.2.2.md，列出：

- 捕获命令总数；
- 客户端已命名数量；
- 双端 typed/raw/unsupported 数量；
- 结构漂移、截断和损坏样例；
- 缺少客户端接收函数的命令；
- 未经确认但当前业务正在使用的字段。

存在抓包目录不得等同于已经解析。

## 只读扫描器

新增 scripts/build_protocol_evidence.py。它接受 capture root、client root、output root
和 report 参数，并提供 check 模式。

扫描器职责：

1. 枚举和验证八位十六进制命令目录；
2. 转换十六进制和十进制命令号；
3. 统计样例、扩展名和 decode kind；
4. 统计 JSON 根类型、数组长度和字段类型；
5. 检测同命令结构差异；
6. 从 NetCommandDef.cs 提取命令常量；
7. 合并人工字段证据；
8. 输出稳定排序的确定性产物；
9. 在 check 模式检测产物过期。

扫描器不得输出聊天、账号、角色名、token 或完整 payload，不得猜测业务字段，不得修改
抓包文件，也不得写入本机绝对路径。

## 人工证据覆盖层

在 protocol/evidence/client-9.2.2 下为高价值命令建立小型证据文件。第一批至少覆盖：

- 0000000a / 10：个人完整战报；
- 0000005c / 92：同盟完整战报；
- 00000067 / 103：同盟成员；
- 0000008f / 143：聊天成员列表；
- 000001fe / 510：玩家统计；
- 0000029f / 671：武将解锁；
- 0000030c / 780：公告；
- 00000834 / 2100：战报通知；
- 00000898 / 2200：通知；
- 000013a2 / 5026：世界场景全量；
- 000013a4 / 5028：世界场景增量。

证据文件只能引用真实存在的客户端源码路径和行号。构建器验证文件存在且命令 ID 与
NetCommandDef.cs 一致。

## 分层边界

通用传输层只负责 TCP 重组、长度检查、解码、单包异常隔离、原始保存和诊断计数，
不得解释业务字段。

命令解析层使用明确的命令注册表。每个 typed 解析器必须校验根类型、长度和字段类型，
保留原始来源，明确可选空值，不吞结构错误，并确保单命令失败不停止抓包。

业务投影层只消费 CLIENT_CONFIRMED 或经批准的 CAPTURE_CONFIRMED 字段。投影失败不得
污染原始捕获。

## Web 与 Android 一致性

两端共享版本化协议契约而非语言实现。自动检查至少覆盖：

- 十六进制和十进制命令 ID；
- 字段 path、类型和空值；
- WID 统一为 x=wid/10000、y=wid%10000；
- 时间戳秒/毫秒单位；
- 赛季武将 raw/base ID；
- profile 数据隔离；
- 同一指标不得使用不同事实源混算。

Android 可生成 Kotlin 常量或契约测试，Web 可生成 Python 注册表；两端不得继续维护无
证据的数字索引副本。

## 数据安全与兼容

- capture_new、数据库和用户档案继续忽略；
- 版本化产物只含结构摘要和源码锚点；
- 第一阶段不删除旧表；
- 新字段通过迁移或兼容查询加入；
- 原始 ID 和来源可追溯；
- 未知命令继续保存且不阻断抓包；
- 单条解析失败不停止后续流量。

## 测试

扫描器测试覆盖 ID 转换、目录验证、结构统计、drift、损坏 JSON、隐私、确定性输出和
check 模式。

真实样例测试只读 capture_new，不复制内容到日志。每个 typed 命令至少验证一个样例、
根类型、必需字段和当前双端槽位。

源码证据测试验证命令常量、引用文件、字段冲突，并禁止未确认字段进入批准的统计指标。

## 第一阶段完成门禁

必须同时满足：

1. 当前 94 个命令全部进入目录；
2. 已有专用解析命令都有 evidence 文件；
3. 未解析命令明确标记 raw 或 unknown；
4. 双端 ID 表示检查通过；
5. 产物无绝对路径和用户内容；
6. 扫描器 check 通过；
7. Python 和 Android 契约测试通过；
8. 报告准确区分捕获、命名、字段化和业务使用。

## 验收结果

第一阶段完成不代表 94 个命令都有页面，而是代表全部命令可追踪、已解析字段有源码和
样例证据、未知内容被诚实标记、双端不再因 ID 和字段索引分叉，后续功能无需重复逆向
或猜测字段。
