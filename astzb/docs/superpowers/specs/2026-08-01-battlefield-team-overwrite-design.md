# 实时战场同队覆盖设计

## 目标

实时战场中，同一 `teamId` 的行军状态只展示最新一条。5026/5028 带来的新位置、路线、到达时间、武将或状态更新覆盖旧卡片，不因时间字段变化持续新增卡片。

## 覆盖边界

- 仅对目标为 `EventTarget.Team` 的行军事件按 `teamId` 覆盖。
- 战报事件按战报 ID 保留历史。
- 攻城事件按现有事件 ID 保留历史。
- 不同 `teamId` 始终分别展示。
- 同一批数据中选择 `occurredAt` 最新的事件；时间相同则使用稳定 ID 顺序决定结果。

## 仓库行为

为 `BattlefieldEvent` 定义仓库内部展示键：

- 行军队伍：`march-team:<teamId>`。
- 其他事件：继续使用 `event.id`。

`visible`、`buffered` 和 `previousSourceEvents` 均使用展示键，避免刷新、暂停和恢复三条路径产生不同去重结果。保存到 Map 前先按时间从新到旧归并，确保同队只保留最新事件。

恢复暂停时，将可见事件与缓冲事件合并；同队缓存的最新状态覆盖暂停前状态。分类筛选只影响显示，不影响覆盖缓存。

## 测试与验收

- 仓库测试：同一队伍两个不同时刻的行军只输出最新一条。
- 仓库测试：不同队伍均保留，战报和攻城历史不被队伍覆盖规则合并。
- 仓库测试：暂停期间收到同队多次更新，恢复后只显示最新状态。
- 完整单元测试、AndroidTest 编译和 APK 构建通过后覆盖安装。
- 真机实时战场确认同一队伍仅一张卡，卡片内容随最新报文更新。
