# Windows 桌面壳、账号认证与一键安装设计

日期：2026-08-16

## 1. 目标

将现有 `stzb_watcher` Web 端封装为 Windows 10/11 x64 桌面程序，并交付标准安装包：

```text
STZB助手-Setup-x64.exe
```

用户安装后通过桌面图标启动，不需要自行安装 Python、Java 或 .NET，不需要打开命令行，也不再由程序打开外部浏览器。程序使用 WebView2 原样承载当前 Dashboard，并在启动本地服务前完成免费账号注册或登录验证。

本软件永久免费。登录和注册页面必须明确展示：

> 本软件完全免费，禁止任何形式的倒卖、付费代装或捆绑销售。

## 2. 已确认范围

### 2.1 首版包含

- Windows 10/11 x64；
- C#/.NET 8 桌面壳；
- WebView2 内嵌当前 Web Dashboard；
- 系统托盘、启动状态、日志入口和进程生命周期管理；
- 内置 Python 后端及全部 Python 依赖；
- 内置精简 Java Runtime 和 Kotlin 战斗引擎；
- Inno Setup 标准安装程序；
- 用户名和密码开放注册；
- 记住登录；
- Ubuntu 公网认证服务；
- 服务端账号禁用和全局服务开关；
- 启动时认证，运行期间不做认证心跳；
- 抓包能力检测；
- 抓包不可用时引导安装官方 Npcap；
- 手动下载安装包覆盖升级。

### 2.2 首版不包含

- Windows 7、32 位 Windows 或 Windows ARM；
- macOS 桌面安装包；
- 自动更新；
- 旧 `D:\nettest` 数据扫描或迁移；
- 邮箱、短信或第三方登录；
- 邮件验证码；
- 找回密码、恢复码或管理员重置密码；
- 会员、付费、激活码或设备数量限制；
- 管理员网页；
- 运行期间账号状态心跳；
- 游戏数据、抓包文件或 SQLite 数据上传；
- 主 Dashboard 的重新设计；
- Npcap 免费版安装器再分发。

## 3. 技术选型

采用：

> C#/.NET 8 + WebView2 + Python 后端 Sidecar + 内置 Java Runtime + Inno Setup

### 3.1 选择 C#/.NET 8 的原因

- 目标平台仅为 Windows，原生窗口、托盘和进程管理更直接；
- self-contained 发布后目标电脑不需要预装 .NET；
- WebView2 可直接加载当前 Web 页面，不需要迁移 Vanilla JS；
- 相比 Electron 体积和常驻资源更低；
- 相比 Tauri，不需要为当前项目引入 Rust 工具链和额外调试面。

### 3.2 WebView2 分发

首版使用随应用部署的 WebView2 Fixed Version Runtime。桌面壳显式指定该运行时目录，不依赖目标电脑是否已安装 Edge WebView2 Evergreen Runtime。

## 4. 总体架构

```text
STZB Desktop Shell
├── 本地登录/注册界面
├── Windows Credential Manager
├── WebView2 主窗口
├── 托盘与运行状态
├── Python 后端进程管理
└── 日志与退出清理
        │
        ├── HTTP → Ubuntu Auth Service
        │             └── 用户、会话、账号状态、全局开关
        │
        └── localhost → Flask Backend
                          ├── Scapy 抓包
                          ├── SQLite
                          ├── SSE
                          ├── 当前 Dashboard
                          └── Java/Kotlin Battle Engine
```

认证服务与游戏数据面严格分离。认证服务只处理账号注册、登录、启动验证、退出和服务状态，不接收任何战报、抓包内容、游戏账号档案或本地数据库。

## 5. Windows 桌面壳

新增独立 `desktop/` C# 工程。桌面壳不实现业务页面，只负责宿主和生命周期。

### 5.1 职责

- 显示登录、注册和启动进度；
- 从 Windows Credential Manager 读取或删除会话令牌；
- 调用认证服务；
- 选择可用的本地监听端口；
- 生成一次性本地管理密钥；
- 启动并监控 Python 后端；
- 轮询后端健康检查；
- 通过 WebView2 打开当前 Dashboard；
- 提供托盘菜单；
- 显示可操作的错误信息；
- 彻底退出时终止自己创建的子进程。

### 5.2 启动状态

桌面壳依次展示：

```text
正在验证账号
正在准备本地数据
正在启动服务
正在检查抓包能力
正在加载界面
```

启动阶段不得显示空白 WebView 或 Python 堆栈。

### 5.3 Web 界面

- 主 WebView 加载 `http://127.0.0.1:<动态端口>/`；
- 当前 Dashboard 的 HTML、CSS、JS、导航结构和业务交互保持不变；
- 桌面化不得改变现有 `208px` 桌面侧栏和响应式行为；
- WebView 导航限制在本地应用地址；
- 外部链接交给系统默认浏览器打开；
- 本地服务未健康前不得加载 Dashboard。

### 5.4 托盘行为

关闭主窗口时默认隐藏到托盘，后端和抓包继续运行。第一次关闭时提示：

> 程序已缩小到系统托盘，数据采集仍在运行。需要停止程序，请在托盘菜单选择“彻底退出”。

用户可以选择以后不再提示。

托盘菜单包含：

- 打开主界面；
- 暂停或恢复抓包；
- 查看运行状态；
- 打开日志目录；
- 重启本地服务；
- 退出登录；
- 彻底退出。

双击托盘图标恢复窗口。只有“彻底退出”才停止本地服务和子进程。

## 6. 本地后端适配

现有 Python 业务能力保持不变，但新增桌面专用启动入口。

### 6.1 启动约束

- 不自动打开系统浏览器；
- 只监听 `127.0.0.1`；
- 监听端口由桌面壳传入；
- 数据根目录由桌面壳传入；
- 管理密钥由桌面壳通过环境变量传入；
- 提供无副作用健康检查；
- 提供受管理密钥保护的停止和抓包暂停接口；
- 模块导入阶段不得自动启动后台线程；
- 安装目录视为只读，不在安装目录创建数据库、日志或抓包文件。

### 6.2 用户数据目录

```text
%LOCALAPPDATA%\STZBWatcher\
├── data\
│   ├── SQLite 数据库
│   ├── profiles.json
│   └── 用户设置
├── captures\
├── logs\
│   ├── desktop.log
│   └── backend.log
└── cache\
```

不扫描、不导入、不修改 `D:\nettest`。升级时保留此目录；卸载时询问用户是否删除。

### 6.3 Python 后端打包

Python 后端作为独立 Sidecar 产物交付，不嵌入 C# 进程。打包产物包含：

- Python 解释器；
- Flask、Flask-CORS、Scapy 等依赖；
- Python 业务模块；
- Dashboard 静态资源；
- 配置快照和必要的数据资源。

Sidecar 与桌面壳分离，便于单独记录日志、重启和定位崩溃。

### 6.4 Kotlin 战斗引擎

- 安装包携带精简 Java Runtime；
- `battle-engine` 以可执行分发形式随应用安装；
- Python adapter 显式使用随包 Java 路径；
- Java 或战斗引擎失败时只降级模拟能力，不阻断 Dashboard、查询和抓包。

## 7. 抓包与 Npcap

### 7.1 能力检测

不能只通过文件或注册表判断驱动存在。桌面端启动后执行真实抓包能力探测：

1. 加载 Scapy 抓包后端；
2. 枚举可用网卡；
3. 创建短时、非持久抓包会话；
4. 验证当前 `tcp and src port 8001` 过滤路径可创建；
5. 返回 `available`、`driver_missing`、`permission_denied` 或 `unknown_error`。

### 7.2 Npcap 引导

- 抓包能力可用时不显示 Npcap 提示；
- 不可用且判断为缺少兼容驱动时，引导用户安装官方 Npcap；
- 安装入口必须指向 Npcap 官方下载页或官方安装程序；
- Npcap 免费版安装器不包含在本项目安装包内；
- 用户完成安装后，桌面壳提供“一键重新检测”；
- Npcap 缺失不阻断 Dashboard、SQLite 查询或战斗模拟；
- 主界面必须明确显示“实时采集未启用”。

如果未来购买 Npcap OEM 对应授权，可独立调整安装步骤，核心桌面架构不变。

## 8. 账号与认证服务

### 8.1 部署目标

- Ubuntu 公网服务器；
- SSH 入口：`ubuntu@152.136.236.184`；
- 首版认证 API 使用固定 IP；
- 首版按用户确认使用 HTTP；
- API 基地址必须集中配置，未来可切换为 HTTPS，不散落在客户端代码中。

服务器凭据、SSH 私钥和管理员秘密不得写入仓库或安装包。

### 8.2 用户规则

- 开放注册；
- 用户名加密码；
- 用户名不区分大小写；
- 用户名规范化后必须唯一；
- 用户名长度 4～24；
- 只允许英文字母、数字和下划线；
- 密码至少 8 个字符；
- 不要求邮箱或手机号；
- 不提供找回密码；
- 不生成恢复码；
- 管理员不能查看、设置或重置用户密码；
- 忘记密码且没有有效会话时只能重新注册新账号。

注册页面必须明确提示：

> 密码无法找回，请自行妥善保存。

### 8.3 API

```text
POST /v1/register
POST /v1/login
POST /v1/session/verify
POST /v1/logout
```

接口统一返回稳定的机器码和用户可读提示，不把数据库错误或堆栈返回给客户端。

### 8.4 注册

请求：

```json
{
  "username": "example_user",
  "password": "user-password",
  "clientVersion": "1.0.0"
}
```

成功后创建账号并返回随机会话令牌。用户名冲突、格式错误、密码过短、全局服务关闭和限流必须使用不同错误码。

### 8.5 登录

登录成功前依次检查：

1. 全局服务是否启用；
2. 账号是否存在；
3. 账号是否启用；
4. 密码是否正确；
5. 客户端版本是否被允许。

成功后返回账号信息、随机会话令牌、服务状态和可选公告。

### 8.6 记住登录

- 客户端不保存密码；
- 会话令牌存入 Windows Credential Manager；
- 服务端只保存令牌哈希；
- 每次程序启动调用 `/v1/session/verify`；
- 验证成功才启动本地后端；
- 令牌无效、账号禁用或用户退出登录时删除本地令牌；
- 本次运行开始后不再执行账号心跳；
- 账号禁用和全局停服在用户下次启动时生效。

### 8.7 密码与令牌存储

- 密码使用 Argon2id 哈希；
- 每个密码使用独立盐；
- 不保存明文密码；
- 会话令牌使用密码学安全随机数生成；
- 数据库只保存令牌哈希；
- 日志不得记录密码、完整令牌或 Authorization 内容。

### 8.8 服务端数据

最小数据模型：

```text
users
- id
- username_normalized
- username_display
- password_hash
- status
- created_at
- last_login_at

sessions
- id
- user_id
- token_hash
- created_at
- last_verified_at
- revoked_at

service_state
- enabled
- announcement
- updated_at

login_attempts
- username_normalized
- source_ip
- succeeded
- created_at
```

### 8.9 防滥用

- 注册和登录按来源 IP 限流；
- 登录失败采用递增延迟；
- 对单一用户名进行失败频率限制；
- 响应不泄露不必要的账号存在性信息；
- 认证服务设置请求体大小、连接和处理超时；
- 数据库写入使用事务；
- 定期清理过期会话和旧登录尝试；
- HTTP 明文风险不能被这些措施消除。

## 9. 服务端管理

不提供管理员网页。管理员通过 SSH 登录 Ubuntu 后使用 CLI：

```bash
stzb-auth user list
stzb-auth user disable <username>
stzb-auth user enable <username>
stzb-auth service disable
stzb-auth service enable
stzb-auth announcement set "说明"
stzb-auth status
```

管理命令不得提供：

- 查看用户密码；
- 设置用户长期密码；
- 重置用户密码；
- 导出完整会话令牌。

全局服务关闭后：

- 新注册失败；
- 用户名密码登录失败；
- 启动会话验证失败；
- 已经通过验证并正在运行的客户端不受影响；
- 客户端下次启动时被阻止。

## 10. HTTP 明文风险

用户已明确选择首版使用固定公网 IP 上的 HTTP。该决定有以下不可消除的风险：

- 登录密码可能被同网段、代理或网络中间节点读取；
- 会话令牌可能被截获并重放；
- 服务端响应可能被篡改；
- 客户端无法可靠确认自己连接的是真实认证服务器。

实现必须保留升级路径：

- 认证 API 基地址集中配置；
- 传输层不参与业务状态机；
- 服务端可直接增加 TLS 反向代理；
- 客户端切换 HTTPS 不改变注册、登录和验证模型。

部署文档必须再次提示该风险。不得把 Argon2id、限流或日志脱敏描述成 HTTP 传输安全的替代品。

## 11. 安装包

### 11.1 安装内容

`STZB助手-Setup-x64.exe` 包含：

- self-contained .NET 8 桌面壳；
- WebView2 Fixed Version Runtime；
- Python Sidecar；
- Flask、Scapy 和其他 Python 依赖；
- 当前 Dashboard 静态资源；

不包含 Npcap 免费版安装器。

### 11.2 安装流程

1. 检查 Windows 10/11 x64；
2. 安装程序和只读资源；
3. 创建桌面和开始菜单快捷方式；
4. 初始化 `%LOCALAPPDATA%\STZBWatcher`；
5. 启动桌面壳；
6. 用户完成注册或登录；
7. 桌面壳启动本地后端；

### 11.3 升级和卸载

- 首版不自动更新；
- 用户下载新版安装包覆盖安装；
- 程序文件可替换；
- `%LOCALAPPDATA%\STZBWatcher` 默认保留；
- 卸载时询问是否删除用户数据；
- 数据删除必须是显式选择，不能默认执行。

## 12. 错误处理

### 12.1 认证服务器不可达

- 停留在登录或启动验证页面；
- 不启动本地后端；
- 提供重试；
- 不允许因缓存令牌绕过启动验证；
- 显示“认证服务器暂时无法连接”，不显示底层 Socket 堆栈。

### 12.2 账号禁用或全局停服

- 不启动本地后端；
- 显示服务端返回的稳定提示和公告；
- 账号禁用时删除本地会话令牌；
- 全局停服时保留令牌，以便服务恢复后自动验证。

### 12.3 本地后端失败

- 显示失败阶段；
- 提供重试、重启和打开日志目录；
- 只清理由本桌面壳启动的进程；
- 不按进程名批量终止其他 Python 或 Java 进程。

### 12.4 抓包不可用

- 其他功能继续运行；
- 状态区显示“实时采集未启用”；
- 区分驱动缺失、权限不足和未知错误；
- 驱动缺失时提供官方 Npcap 安装入口；
- 提供重新检测。

### 12.5 战斗引擎失败

- Dashboard 和其他 API 继续可用；
- 模拟页面显示战斗引擎不可用；
- 日志记录 Java 退出码和脱敏后的错误摘要。

### 12.6 WebView2 失败

- 提供重新加载；
- 提供重启本地服务；
- 提供打开日志目录；
- 不自动退回系统浏览器作为常规运行方式。

必须在干净的 Windows 10/11 x64 机器验证：

1. 未安装 Python、Java、.NET 时可完成安装；
2. 不依赖系统 Edge WebView2 Runtime；
3. 可以注册、登录和记住登录；
4. 重启程序后自动验证并进入主界面；
5. 当前 Dashboard 页面和交互保持一致；
6. 已有兼容抓包能力时不显示 Npcap 提示；
7. 无抓包能力时正确引导官方 Npcap；
8. 安装 Npcap 后重新检测成功；
9. 能抓包、写入 SQLite 并显示实时事件；
10. Kotlin 战斗模拟可运行；
11. 关闭窗口后托盘继续工作；
12. 彻底退出后没有遗留后台进程；
13. 服务端禁用账号后，下次启动被阻止；
14. 全局停服后，下次启动被阻止；
15. 运行中的客户端不受后续停服状态影响；
16. 覆盖安装不丢失数据库、抓包和用户设置；
17. 卸载按用户选择保留或删除本地数据；
18. 认证服务不可达时不会绕过启动认证；
19. 日志中不存在密码或完整令牌。

## 15. 实施边界

实施拆为两个可独立验证但最终集成的交付面：

1. **Ubuntu 认证服务**
   - API、数据库、CLI、部署和备份；
2. **Windows 桌面发行版**
   - 桌面壳、后端适配、运行时打包、安装程序和 Windows 验收。

认证 API 契约先稳定，再接入桌面壳。Dashboard 业务页面不参与账号认证；认证只发生在桌面壳启动本地服务之前，避免把公网账号逻辑散布到现有 Web 页面。

## 16. 完成定义

首版完成必须同时满足：

- 用户从单个 `STZB助手-Setup-x64.exe` 完成应用主体安装；
- 除 Npcap 官方安装引导外，不需要手工配置运行环境；
- 注册或登录成功后才能启动本地服务；
- 登录页明确标注软件永久免费、禁止倒卖；
- Dashboard 界面和现有业务行为保持一致；
- 本地抓包和游戏数据不上传认证服务器；
- 账号禁用与全局停服在下次启动生效；
- 关闭到托盘和彻底退出行为符合设计；
- 干净 Windows 10/11 x64 机器通过完整安装验收。
