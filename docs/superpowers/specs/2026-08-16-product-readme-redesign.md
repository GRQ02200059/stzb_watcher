# stzb_watcher 产品型 README 重构设计

日期：2026-08-16  
状态：已确认，待实施

## 目标

将仓库 README 从偏开发者的长篇技术说明，重构为面向普通用户的产品主页。
读者应在一分钟内理解：

1. 这是什么产品；
2. 能解决哪些游戏数据与战场决策问题；
3. 实际界面是什么样；
4. 如何在本机启动；
5. 去哪里查看进阶技术资料。

README 不再承担完整架构文档、API 字典和 HUD 实现规范的职责。这些内容继续保留
在 `docs/`、源码和测试中。

## 内容策略

### 主要受众

- 想了解项目能力的普通用户；
- 希望快速运行项目的个人使用者；
- 从 GitHub 首页判断项目成熟度的访问者。

开发者信息保留为末尾的精简章节，不占据首屏和主要阅读路径。

### 文案风格

- 使用中文；
- 先展示结果，再解释实现；
- 避免内部类名、请求 revision、loader 生命周期等实现细节；
- 每段不超过四行，优先使用短列表和卡片式表格；
- 不使用 Emoji；
- 不夸大未经验证的协议、概率或模拟准确度。

## 页面结构

README 目标长度约 200–280 行，按以下顺序组织：

1. **产品首屏**
   - 项目名称；
   - 一句话定位；
   - Python、Flask、Vanilla JS、Kotlin、测试状态等简洁徽章；
   - 快速链接：界面预览、快速开始、核心功能、项目结构。

2. **全景主图**
   - 使用“战场情报”页面；
   - 展示完整 208px 侧栏、顶栏、地图、图层与右侧情报区；
   - 图片宽度适合 GitHub 桌面页面全宽展示。

3. **核心价值**
   - 战场态势统一；
   - 实时部队与行军；
   - 阵容研究与模拟；
   - 团队管理与赛季积分。

4. **六图功能画廊**
   - 实时部队；
   - 战斗模拟；
   - 阵容战法研究；
   - 自定义积分；
   - 打城考勤；
   - 玩家队伍。
   - 使用两列表格，每张图下方只保留一句用户价值说明。

5. **功能总览**
   - 将 12 个主导航页面按“情报、行动、组织、分析、系统”五个视觉域归类；
   - 不展开每个 API 或内部状态机。

6. **三步快速启动**
   - 安装 Python 依赖；
   - 构建 Kotlin 战斗引擎；
   - 启动 `api_server.py` 并访问 `http://127.0.0.1:8080`。
   - 补充 Python、Java 和 Chrome 的最低环境说明。

7. **数据与隐私**
   - 说明抓包、SQLite、运行态账号文件的本地存储位置；
   - 说明 `current_profile.json`、`profiles.json`、数据库和抓包文件不会提交；
   - 提醒公开部署时配置写接口 Token。

8. **精简技术说明**
   - 用一张 Mermaid 流程图说明 Capture → Parse → SQLite → API/SSE → Dashboard；
   - 用短表格列出后端、前端、实时链路与战斗引擎；
   - 链接到 `docs/superpowers/specs/` 和 `docs/research/`。

9. **测试与许可**
   - 提供 Node 与 Python 两条标准验证命令；
   - 保留项目用途和授权提示；
   - 保留作者联系方式，但降低视觉权重。

## 截图方案

### 图片清单

截图统一保存到：

`docs/assets/screenshots/`

文件名固定为：

- `overview-intelligence.webp`：全景主图，战场情报；
- `gallery-live-army.webp`：实时部队；
- `gallery-simulator.webp`：战斗模拟；
- `gallery-research.webp`：阵容战法研究；
- `gallery-score.webp`：自定义积分；
- `gallery-attendance.webp`：打城考勤；
- `gallery-player-teams.webp`：玩家队伍。

### 截图来源

- 使用当前本地服务 `http://127.0.0.1:8080`；
- 使用当前页面真实数据；
- 不伪造统计值，不插入演示数据；
- 截图前等待页面 loading 状态结束；
- 保留真实角色名、区服和战报信息，不打码；
- 不截取浏览器地址栏、开发者工具或系统桌面。

### 视觉规格

- 全景主图使用 1440px 视口，覆盖完整页面首屏；
- 六张画廊图统一使用 1200px 视口和相同宽高比；
- 优先使用 WebP，兼顾清晰度和仓库体积；
- 单张主图目标不超过 450KB；
- 单张画廊图目标不超过 300KB；
- 七张图片总目标不超过 2.2MB；
- 不增加 GIF、视频或持续动画资源。

### 截图状态

- 战场情报：地图与主要图层可见；
- 实时部队：三栏指挥台完整可见；
- 战斗模拟：双方阵容与快速对阵区可见；
- 阵容战法研究：三栏研究工作台可见；
- 自定义积分：榜单、筛选和规则入口可见；
- 打城考勤：任务阶段和成员区域可见；
- 玩家队伍：队伍列表和主要操作区可见。

若真实数据为空，允许展示产品自身的 empty/stale 状态，但不得通过修改数据库制造
截图内容。

## README 保留与删除

### 保留

- 项目定位；
- 核心功能；
- 快速启动；
- 数据目录和 Token 说明；
- 标准测试命令；
- 精简项目结构；
- 技术资料入口；
- 联系方式与许可说明。

### 移出 README

- HUD 事件白名单的逐项实现说明；
- Surface token 的完整规范；
- loader、revision、Abort 和竞态处理细节；
- 全部 API endpoint 字典；
- 画像、卡包、研究快照和战斗引擎同步的长篇命令说明；
- 已迁移或仅供历史参考的旧页面说明。

这些内容已经存在于设计文档、计划、源码和测试中，不需要在产品首页重复。

## 验收标准

1. README 首屏在不滚动代码细节的情况下展示产品定位和全景图；
2. 七张图片均为本项目真实页面，路径有效；
3. 六图画廊在 GitHub 桌面端保持两列，在窄屏自然纵向排列；
4. README 中的启动命令可以从干净环境理解并执行；
5. 不引用已经删除的 `dashboard/` 原型或根目录旧导出 JSON；
6. 不包含本机绝对路径作为用户必需配置；
7. Markdown 链接和图片引用全部指向仓库内存在的文件；
8. 图片总大小不超过 2.2MB；
9. Node 与 Python 全量回归继续通过；
10. `git diff --check` 通过。

## 非目标

- 不修改产品 UI；
- 不新增功能或 API；
- 不修改真实数据库；
- 不重新设计 Logo；
- 不创建动态图、视频或外部图床；
- 不重写 Git 历史；
- 不在本任务中删除旧 Vue 模拟器或合并重复配置快照。
