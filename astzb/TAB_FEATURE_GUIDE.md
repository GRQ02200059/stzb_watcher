# st助手安卓独立版 标签页功能说明文档
源码地址见  https://github.com/GRQ02200059/stzb_watcher 欢迎star


## 1. 文档范围

本文档聚焦 Dashboard 左侧侧栏中的业务标签页，不展开讲解安装、出包和 VPN 授权本身。


## 2. 标签页总览

### 2.1 侧栏打开方式

- 通过左上角 `菜单` 按钮打开侧栏
- 点击遮罩关闭侧栏
- 侧栏已打开时，可左滑收起

说明：

- 当前版本不支持通过边缘左滑直接唤起侧栏

### 2.2 标签页名称与排列顺序

当前侧栏标签页按以下顺序排列：

1. 全服玩家队伍
2. 全部战报
3. 同盟成员
4. 分组武勋
5. 工程考勤
6. 同盟成员队伍
7. 战场消息
8. 团数据
9. 战斗模拟
10. 州郡分布
11. 实时队伍监控
12. 辅助战场监控

### 2.3 全局共用界面元素

大部分标签页共用以下结构：

- 模块标题：显示当前页名称
- 模块副标题：说明当前页核心定位
- KPI 摘要栏：显示该页关键统计
- 内容区：卡片流或列表
- 状态栏：显示“加载中 / 已刷新 / 导出完成 / 失败”等提示
- 过滤区：只在部分页面出现
- 子标签栏：只在部分复杂页面出现

### 2.4 主要数据来源

各页面并不是独立抓取，而是共享同一条本地数据链路：

```text
抓包 -> 协议解析 -> SQLite 入库 -> 各业务页按需聚合展示
```

核心数据来源包括：

- `10 / 92` 完整战报
- `2100` 战报通知 / 聊天消息
- `5028` 实时队伍监控
- `5026 / 13A2` 地块与辅助索引
- `103` 同盟成员
- `700` 排行数据
- `6243` 战区玩家
- `90005` 数据同步记录

这意味着多个页面之间会共享同一批底层数据，只是展示口径不同。

## 3. 页面关系总图

### 3.1 一级关系

- `全部战报` 是很多分析页的基础数据源
- `同盟成员` 为 `同盟成员队伍`、`工程考勤`、`州郡分布` 提供成员范围基础
- `实时队伍监控` 与 `辅助战场监控` 相互补充
  - 前者偏 5028 实时流
  - 后者偏 5026 / 13A2 结构索引
- `团数据`、`分组武勋`、`工程考勤` 都依赖战报聚合结果
- `战斗模拟` 相对独立，不依赖实时抓包结果即可运行

### 3.2 二级页面关系

当前存在明显“主页面 -> 子标签页”的模块：

- 同盟成员
  - 主页
  - 成员概览
  - 成员队伍
- 工程考勤
  - 任务主页
  - 概览
  - 成员
  - 战报
  - 操作
- 州郡分布
  - 总览
  - 州郡
  - 同盟
  - 分组

## 4. 标签页详细说明

## 4.1 全服玩家队伍

### 4.1.1 核心功能

- 从完整战报中聚合玩家队伍
- 按玩家、同盟、攻守方、武将、战法进行筛选
- 展示队伍构成、胜率和主要阵容信息

### 4.1.2 主要用途

- 查看当前服务器内高频队伍
- 找某个玩家或同盟常用阵容
- 按武将 / 战法反查对应队伍

### 4.1.3 目标用户场景

- 想快速查看某玩家阵容配置
- 想对比不同队伍胜率
- 想从战报中做阵容检索

### 4.1.4 主要界面元素

- 顶部筛选栏
  - 玩家
  - 同盟
  - 攻守方
  - 武将 / 战法关键字
- KPI 摘要
  - 匹配队伍数
  - 当前展示条数
  - 平均胜率
- 队伍卡片列表

### 4.1.5 交互逻辑与操作流程

1. 打开页面
2. 系统加载本地聚合后的玩家队伍
3. 输入玩家 / 同盟 / 攻守 / 武将关键词
4. 列表自动按筛选结果刷新
5. 点击卡片查看该队伍详情

### 4.1.6 关键功能点

- 支持模糊搜索玩家名
- 支持模糊搜索同盟名
- 支持按攻方 / 守方筛选
- 支持按武将名、武将 ID、战法名联合搜索
- 卡片可显示阵容结构与胜率

### 4.1.7 数据关联

- 主要来自 `10 / 92` 完整战报
- 与 `同盟成员队伍` 共用部分队伍聚合逻辑
- 与 `战斗模拟` 一样都关注阵容，但前者基于真实战报，后者基于模拟配置

### 4.1.8 特殊 / 异常场景

- 本地战报不足时，队伍页内容会偏少
- 如果关键词过多，可能出现“有战报但无匹配队伍”的空结果

## 4.2 全部战报

### 4.2.1 核心功能

- 展示本机完整战报列表
- 优先读取 `10 / 92` 完整战报
- 无完整战报时使用 `2100` 战报通知兜底

### 4.2.2 主要用途

- 作为战报浏览主入口
- 快速查看结果、类型、时间、武勋、目标坐标
- 进入战报详情页

### 4.2.3 目标用户场景

- 核对近期战报是否已抓到
- 查某一场战斗结果
- 根据玩家、同盟、时间、坐标筛选目标战报

### 4.2.4 主要界面元素

- 顶部筛选栏
  - 玩家
  - 同盟
  - 战斗类型
  - 结果
  - wid
  - 开始时间
  - 结束时间
- KPI 摘要
  - 总战报数
  - 胜 / 负 / 平数量
  - 数据来源
- 战报卡片列表

### 4.2.5 交互逻辑与操作流程

1. 打开页面
2. 页面优先读取完整战报
3. 若完整战报为空，则回退到通知战报
4. 用户输入筛选条件
5. 战报卡片列表刷新
6. 点击卡片进入战报详情页

### 4.2.6 关键功能点

- 支持多条件联合筛选
- 战报卡片有明显的胜 / 负 / 平状态徽记
- 显示时间、战斗类型、攻守双方、武勋、目标坐标
- 作为多个分析页的数据来源入口

### 4.2.7 跳转关系与数据关联

- 点击战报可进入 `BattleDetailActivity`
- `全服玩家队伍`、`分组武勋`、`团数据`、`工程考勤` 都依赖这里的战报数据做聚合

### 4.2.8 特殊 / 异常场景

- 若 `10 / 92` 缺失，只会显示 `2100` 通知兜底数据
- 如果筛选过严，可能出现空列表

## 4.3 同盟成员

### 4.3.1 核心功能

- 展示同盟成员总览
- 按分组筛选成员
- 支持分组折叠 / 展开
- 支持成员详情子页

### 4.3.2 主要用途

- 查看同盟成员规模、分组、势力、武勋、贡献
- 进入单个成员详情
- 继续查看该成员的队伍信息

### 4.3.3 目标用户场景

- 管理者查看各团成员情况
- 查询成员势力与武勋排名
- 查看某一成员目前已有的本地队伍信息

### 4.3.4 主要界面元素

- 顶部分组切换子标签
  - 全部
  - 各个分组
- 同盟总览卡
- 分组汇总卡
- 成员卡片
- 成员详情子标签
  - 返回成员页
  - 概览
  - 队伍

### 4.3.5 交互逻辑与操作流程

1. 打开页面
2. 页面显示同盟总览和分组列表
3. 点击某个分组标签过滤成员
4. 点击分组卡展开 / 收起成员列表
5. 点击某个成员卡进入成员详情子页
6. 在“概览 / 队伍”子页间切换
7. 点击“返回成员页”回到成员主页

### 4.3.6 关键功能点

- 分组过滤
- 分组展开 / 收起
- 成员详情页
- 成员队伍子页
- 对空状态有明确提示

### 4.3.7 跳转关系与数据关联

- `同盟成员队伍` 是这个页面的延展视角
- `工程考勤` 任务成员范围会参考同盟成员
- `州郡分布` 的分组计算也与成员数据有关

### 4.3.8 特殊 / 异常场景

- 成员有但本地没有该成员战报时，“队伍”子页会显示暂无数据
- 未分组成员会归为“未分组”

## 4.4 分组武勋

### 4.4.1 核心功能

- 展示分组维度团报
- 展示成员维度团报
- 将“分组”和“成员”统一放到一条卡片流中

### 4.4.2 主要用途

- 快速比较不同分组的武勋产出
- 再下钻到成员级武勋表现

### 4.4.3 目标用户场景

- 团长 / 管理查看各团贡献差异
- 查某个成员在所属分组中的表现

### 4.4.4 主要界面元素

- 分组卡片
- 成员卡片
- KPI 摘要

### 4.4.5 交互逻辑与操作流程

1. 打开页面
2. 页面先加载分组团报
3. 再加载成员团报
4. 结果按“先分组、后成员”的顺序展示

### 4.4.6 关键功能点

- 直接比较分组与成员两层数据
- 承接网页端分组武勋页思路
- 数据与团数据同源，但视图更直接

### 4.4.7 数据关联

- 依赖完整战报聚合
- 与 `团数据` 数据源相关，但这里更偏武勋导向

### 4.4.8 特殊 / 异常场景

- 若分组信息不完整，部分成员会落到未分组口径

## 4.5 工程考勤

### 4.5.1 核心功能

- 管理工程任务
- 录入任务信息
- 统计成员到勤、主力、拆迁与对应战报
- 导出 CSV
- 删除任务

### 4.5.2 主要用途

- 建立攻城 / 工程任务台账
- 统计实际出勤
- 按任务维度复盘

### 4.5.3 目标用户场景

- 管理者安排攻城任务
- 战后核对哪些成员参与、参与了几次
- 导出任务统计给外部复盘

### 4.5.4 主要界面元素

- 任务主页卡片
  - 新建工程任务
  - 刷新工程考勤
  - 任务总览
  - 任务卡列表
- 任务详情子标签
  - 返回任务页
  - 概览
  - 成员
  - 战报
  - 操作

### 4.5.5 交互逻辑与操作流程

1. 打开页面
2. 默认进入任务主页
3. 点击“新建工程任务”创建任务
4. 点击任务卡进入该任务子页
5. 在“概览 / 成员 / 战报 / 操作”间切换
6. 通过“操作”子页执行统计、导出、删除
7. 点击“返回任务页”回到主任务列表

### 4.5.6 关键功能点

- 新建任务
  - 填写任务名
  - 输入 WID 或 X,Y
  - 设置任务时间
  - 设定目标成员范围
- 任务概览
  - 目标人数
  - 已出战人数
  - 任务坐标
  - 指定成员 / 分组
- 成员页
  - 主力次数
  - 拆迁次数
  - 队伍数
- 战报页
  - 只显示当前任务相关战报
- 操作页
  - 开始统计
  - 导出 CSV
  - 删除任务

### 4.5.7 跳转关系与数据关联

- 数据依赖 `全部战报` 和 `同盟成员`
- 任务范围与坐标决定“成员页 / 战报页”的计算口径

### 4.5.8 特殊 / 异常场景

- 如果当前没有任务，会停留在任务主页
- 如果任务有定义但本地战报不足，成员 / 战报页可能为空
- 导出失败时会有状态栏提示

## 4.6 同盟成员队伍

### 4.6.1 核心功能

- 仅展示“同盟成员集合”对应的队伍
- 过滤掉非成员队伍

### 4.6.2 主要用途

- 从全服队伍中抽出我方同盟成员的常用队伍
- 便于管理视角聚焦己方阵容

### 4.6.3 目标用户场景

- 查看本盟成员主力队伍
- 为排兵布阵或考勤复盘提供参考

### 4.6.4 主要界面元素

- 成员队伍卡片列表
- KPI 摘要

### 4.6.5 交互逻辑与操作流程

1. 打开页面
2. 系统先读取同盟成员名单
3. 再从全服玩家队伍中筛出成员相关队伍
4. 用户浏览队伍详情

### 4.6.6 关键功能点

- 仅保留成员相关队伍
- 适合与同盟成员页联动阅读

### 4.6.7 数据关联

- 依赖 `同盟成员`
- 依赖 `全服玩家队伍`

### 4.6.8 特殊 / 异常场景

- 如果成员数据为空，过滤范围会失效或结果较少

## 4.7 战场消息

### 4.7.1 核心功能

- 展示通用业务记录与消息类数据
- 按消息类型分组输出卡片

### 4.7.2 主要用途

- 查看非核心战报类的战场记录
- 观察消息流与辅助业务数据

### 4.7.3 目标用户场景

- 调试抓包链路
- 关注消息类业务记录
- 查某种协议是否已入库

### 4.7.4 主要界面元素

- 消息卡列表
- 每张卡片包含类型、摘要与详细文本

### 4.7.5 交互逻辑与操作流程

1. 打开页面
2. 页面读取本地 `local_records`
3. 按类型分组输出卡片
4. 用户点击卡片查看详细内容

### 4.7.6 关键功能点

- 适合辅助调试
- 与战报不同，这里强调“消息流”

### 4.7.7 数据关联

- 与 `全部战报`、`实时队伍监控` 互补
- 某些协议可能先在这里看到摘要，再在专页中看到结构化结果

### 4.7.8 特殊 / 异常场景

- 若当前抓包量很少，消息页可能条目很少

## 4.8 团数据

### 4.8.1 核心功能

- 提供团报统计中心
- 支持统计周期切换
- 支持按分组 / 按成员切换
- 支持按分组筛选
- 支持导出 CSV

### 4.8.2 主要用途

- 从组织视角查看战斗贡献
- 观察分组与成员的胜率、战报数、攻城场次和总武勋

### 4.8.3 目标用户场景

- 团长复盘某一周期的整体表现
- 按团或按成员拉战报统计
- 导出汇总结果做外部分析

### 4.8.4 主要界面元素

- 顶部子标签
  - 周期切换
  - 维度切换
  - 分组筛选
- 汇总统计卡
- 明细卡列表
- 导出入口

### 4.8.5 交互逻辑与操作流程

1. 打开页面
2. 默认按当前周期和维度加载数据
3. 用户切换周期
4. 用户切换“按分组 / 按成员”
5. 用户按指定分组筛选
6. 用户导出 CSV

### 4.8.6 关键功能点

- 周期维度：今日 / 昨日 / 本周 / 上周 / 全部
- 统计维度：按分组 / 按成员
- 分组筛选
- 导出 CSV
- KPI 统计
  - 总战报
  - 胜率
  - 参战人数
  - 攻城次数

### 4.8.7 数据关联

- 强依赖完整战报聚合
- 与 `分组武勋` 数据同源，但 `团数据` 更完整、更偏报表

### 4.8.8 特殊 / 异常场景

- 如果周期内战报很少，部分统计卡会出现低样本结果
- 导出失败会在状态栏反馈

## 4.9 战斗模拟

### 4.9.1 核心功能

- 运行本机战斗模拟
- 支持单次与批量模拟
- 支持编辑攻守双方阵容、等级、进阶、战法、士气

### 4.9.2 主要用途

- 预估阵容对抗结果
- 做胜率测试
- 对比不同战法组合

### 4.9.3 目标用户场景

- 研究阵容强度
- 调整战法组合
- 用 100 次 / 1000 次模拟观察稳定胜率

### 4.9.4 主要界面元素

- 操作卡
  - 开始战斗
  - 批量模拟 x100
  - 批量模拟 x1000
- 攻方队伍卡
- 守方队伍卡
- 模拟结果卡
- 模拟器资源卡

### 4.9.5 交互逻辑与操作流程

1. 打开页面
2. 查看默认攻守阵容
3. 点击攻方或守方卡进入编辑器
4. 修改武将、等级、进阶、额外战法
5. 保存后返回页面
6. 点击“开始战斗 / x100 / x1000”
7. 查看结果卡与详细日志

### 4.9.6 关键功能点

- 单次详细模拟
- 100 次批量模拟
- 1000 次批量模拟
- 阵容编辑
  - 武将选择
  - 等级
  - 进阶
  - 战法槽位
- 结果输出
  - 胜负次数
  - 胜率
  - 首场详细战报

### 4.9.7 数据关联

- 相对独立，不依赖实时抓包即可运行
- 与 `全服玩家队伍` 形成“真实战报阵容”与“模拟阵容”的互补关系

### 4.9.8 特殊 / 异常场景

- 某些特殊战法机制可能仍有继续细化空间
- 如果资源未加载成功，页面会给出加载失败提示

## 4.10 州郡分布

### 4.10.1 核心功能

- 统计成员在各州的分布
- 支持按同盟、分组、州维度查看
- 支持全部成员 / 仅指定团切换
- 支持人数 / 势力值两种排序维度

### 4.10.2 主要用途

- 查看成员在地图上的州郡分布态势
- 比较不同同盟、不同分组的地域覆盖
- 判断某个团的区域部署情况

### 4.10.3 目标用户场景

- 战略管理者查看区域态势
- 统计某团当前分布在哪些州
- 从人数与势力两种口径看部署重点

### 4.10.4 主要界面元素

- 顶部子标签
  - 总览
  - 州郡
  - 同盟
  - 分组
- 范围切换
  - 全部成员
  - 仅指定团
- 团选择器
- 排序维度切换
  - 人数
  - 势力值
- 统计卡
- 各类排行卡

### 4.10.5 交互逻辑与操作流程

1. 打开页面
2. 默认以全部成员展示总览
3. 在“总览 / 州郡 / 同盟 / 分组”之间切换
4. 切换统计范围为“仅指定团”
5. 点击“选择团”打开搜索 Picker
6. 在“人数 / 势力值”之间切换排序维度
7. 浏览对应卡片列表

### 4.10.6 关键功能点

- 多页签展示
- 指定团筛选
- 搜索 Picker 选团
- 人数 / 势力值切换
- 同盟 / 分组 / 州三级视角

### 4.10.7 数据关联

- 依赖 `700` 排行、`6243` 战区玩家、成员分组逻辑
- 分组采用“名字前缀分组”口径
- 与 `同盟成员` 共享成员视角，但这里更偏地理分布

### 4.10.8 特殊 / 异常场景

- 若当前没有可筛选的团，选择器会提示无数据
- 若切到“仅指定团”但未选团，则默认仍处于待选状态

## 4.11 实时队伍监控

### 4.11.1 核心功能

- 复刻网页端 5028 实时监控流
- 按快照展示最新队伍动态

- 可结合 13A2 结果显示阵容与战绩洞察

### 4.11.2 主要用途

- 观察实时队伍行军
- 查看目标、当前位置、到达时间
- 结合阵容和战绩做即时判断

### 4.11.3 目标用户场景

- 实时盯盘
- 查某个玩家或某个坐标的动向
- 判断某支队伍是主力还是拆迁

### 4.11.4 主要界面元素

- 顶部搜索过滤区
  - 玩家
  - 同盟
  - 队伍 ID / 坐标
  - 目标 wid
- 总览卡
- 快照卡
- 队伍详情卡

### 4.11.5 交互逻辑与操作流程

3. 每 5 秒自动刷新
4. 用户输入玩家 / 同盟 / 队伍 ID / 坐标 / wid 做过滤
5. 页面显示过滤后的快照和队伍卡

### 4.11.6 关键功能点

  - 速度
- 阵容洞察
  - 武将
  - 战法
  - 最近战绩
  - 克制 / 被克制阵容

### 4.11.7 数据关联

- 阵容与战绩洞察由 `13A2 / 战报聚合` 辅助补充

### 4.11.8 特殊 / 异常场景

## 4.12 辅助战场监控

### 4.12.1 核心功能

- 复刻网页端 13A2 辅助监控页
- 关注地块、主体、队伍、阵容、战绩的综合索引

### 4.12.2 主要用途

- 作为实时监控的辅助视角
- 查看 5026 / 13A2 的结构化信息
- 用地块和队伍双线索理解战场态势

### 4.12.3 目标用户场景

- 想看地图格子与队伍的对应关系
- 想确认某个目标格子周边有哪些队伍
- 用于补充 5028 页不够直观的地图上下文

### 4.12.4 主要界面元素

- 辅助监控总览卡
- 队伍索引卡
- 地块卡
- 战绩 / 阵容说明信息

### 4.12.5 交互逻辑与操作流程

### 4.12.6 关键功能点

### 4.12.8 特殊 / 异常场景

## 5. 页面联动说明

### 5.1 数据联动

- `全部战报` 是分析类页面最重要的底层来源
- `同盟成员` 是组织类页面的基础来源
- `实时队伍监控` 与 `辅助战场监控` 共同构成战场态势页
- `团数据`、`分组武勋`、`工程考勤` 都是对战报的不同聚合口径

- 同盟成员主页 -> 成员概览 / 成员队伍
- 工程考勤主页 -> 任务概览 / 成员 / 战报 / 操作
- 州郡分布主页 -> 总览 / 州郡 / 同盟 / 分组

## 7. 异常与特殊说明

- 若当前抓包不足，很多页面会进入空状态，这是正常现象
- `实时队伍监控` 会自动刷新，其他页面通常需要手动刷新
- `辅助战场监控` 在解析不足时会回退到地块兜底视图
- `工程考勤`、`团数据` 支持导出，失败时会在状态栏提示
- `同盟成员`、`州郡分布` 的分组逻辑采用前缀分组，不是简单同名匹配
