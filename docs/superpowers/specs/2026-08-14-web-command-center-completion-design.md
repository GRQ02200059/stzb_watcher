# STZB Web 战场指挥中心全量完善设计

日期：2026-08-14
状态：用户授权按推荐方案自动推进
优先级：Web 第一，Android 暂不扩展

## 1. 目标与验收边界

本轮把当前静态 Dashboard 升级为可长期使用的桌面战场指挥中心，而不是只做换肤。

必须完成：

1. 现有 Web API 对应的业务模块都有可达入口，不再依赖隐藏 Tab。
2. 新增统一“战场总览”，汇总服务链路、关键指标、最新战报、实时事件和快捷入口。
3. 统一导航、筛选、加载、空态、错误、反馈、键盘与移动端交互。
4. 保留全部既有 ID、Tab 索引、API 契约、SSE、Query Agent、世界场景和战斗模拟器能力。
5. 补齐真实可用的设置中心，包括刷新频率、紧凑模式、动效、声音和本地偏好。
6. 新增创意能力：全局命令面板、战术预警、收藏视图、事件时间线和战场态势摘要。
7. 禁止真实游戏自动操作、主动发包、数据库任意写入和无人值守控制。

“全部实现”以当前仓库已有 API、README 功能、Web Tab 和 Web TODO 为确定边界。Android TODO 不纳入本轮 Web 第一阶段。

## 2. 实施策略

采用渐进增强，不重写现有 4000 行 `app2.js`：

- `dashboard.html` 保留业务 DOM，增加总览、设置和全局交互挂载点。
- `dashboard-design-system.css` 作为统一视觉与响应式覆盖层。
- `dashboard-design-system.js` 负责导航、页面元信息、偏好与基础组件增强。
- 新增 `dashboard-command-center.js`，只负责总览、命令面板、告警、收藏和事件时间线。
- 后端只新增聚合型只读接口；现有业务接口保持兼容。

这样可将新体验与遗留业务逻辑隔离，任何增强脚本失败时原页面仍可使用。

## 3. 信息架构

主导航分组：

- 指挥：战场总览、全部战报、战场监控、世界场景、战场消息
- 同盟：团数据、同盟成员、成员队伍、分组武勋、攻城考勤
- 洞察：排行榜、战场分析、武将阵容、州郡分布、城池地图
- 工具：玩家队伍、战斗模拟、战术检索、设置中心
- 高级：13A2 队伍索引、公告、战区玩家、数据同步、自定义积分

旧 Tab 索引不变。新增：

- `tab31`：战场总览，作为默认首页。
- `tab32`：设置中心。

隐藏但已具备业务实现的页面通过“高级”分组恢复可达。

## 4. 战场总览

总览聚合：

- 当前档案、数据库、抓包和 writer 状态。
- 战报总量、今日战报、活跃行军、同盟成员、城池/地块数量。
- 最新战报列表和胜负分布。
- 最新 SSE 事件时间线。
- 战术预警：即将到达、集中攻击、数据中断、异常链路。
- 收藏视图：用户本地收藏的 WID、玩家、队伍和战报。
- 模块快捷入口。

总览接口为 `GET /api/command-center/overview`。接口只读，并对缺失的可选表降级为空数据，不因单表缺失导致整个页面失败。

## 5. 全局命令面板

快捷键 `Ctrl/Cmd + K` 打开命令面板：

- 按名称搜索全部页面并跳转。
- 执行刷新当前页、切换紧凑模式、暂停/恢复实时更新。
- 输入 WID、队伍 ID 或玩家名时提供战术检索入口。
- 最近访问与收藏操作保存在 `localStorage`。

命令只触发 UI 动作，不直接发起危险后端写操作。

## 6. 战术预警与时间线

前端从总览聚合数据和 SSE 事件生成可解释预警：

- 行军到达时间小于阈值。
- 同一目标 WID 存在多支活跃队伍。
- writer 错误数增加。
- SSE 断开或数据超过阈值未更新。

每条预警必须含等级、文字原因、关联实体、时间和可执行 UI 跳转。用户可静音某类预警，偏好保存在本地。

时间线支持类型筛选、暂停、清空本地视图和“查看最新”；暂停期间事件进入缓冲区，不改变滚动位置。

## 7. 设置中心

设置项：

- 自动刷新：关闭、5 秒、10 秒、30 秒。
- 信息密度：舒适、紧凑。
- 动效：完整、精简。
- 声音提醒：关闭、仅危险、全部。
- 默认首页。
- 右侧情报栏开关。
- 重置本地偏好。

设置即时生效并持久化。系统 `prefers-reduced-motion` 优先于用户完整动效设置。

## 8. 交互与视觉

- 深海军蓝指挥台风格，有限蓝紫渐变与动态网格背景。
- 页面切换使用轻量淡入与位移动画，不使用缩放 hover。
- KPI 采用数字滚动；实时状态使用呼吸点但尊重 reduced motion。
- 表格支持吸顶表头、行聚焦、横向安全滚动和移动端卡片化。
- 所有按钮最小交互高度 40px，图标按钮有可访问名称。
- 加载采用骨架屏，错误态提供重试，空态给出下一步动作。
- Toast、Dialog、Drawer、Command Palette 使用统一层级与焦点管理。

## 9. 后端与错误处理

聚合接口使用独立查询函数，每个指标单独容错。SQLite 缺表返回默认值，数据库不可用返回结构化 `ok=false` 和可读错误。

`api_server.py` 的后台线程启动副作用不在本轮大改，但新增测试不得依赖真实 profile 数据库。测试使用临时 SQLite 和 Flask test client。

## 10. 测试

自动化覆盖：

- 总览接口在完整库和缺表库下均返回稳定 schema。
- Dashboard 包含新增总览、设置、命令面板与脚本挂载点。
- 导航覆盖所有现有业务 Tab。
- 命令面板、偏好、时间线、预警和收藏存在明确静态契约。
- 原 Query Agent、世界场景、模拟器和现有 API 测试全部回归。

浏览器验收：

- 1440px 桌面、1024px 小桌面、768px 平板、375px 手机。
- 主导航、命令面板、总览跳转、设置持久化、SSE 时间线。
- 键盘导航、焦点可见性、reduced motion、无页面级横向溢出。

## 11. 非目标

- 不把 Vanilla JS 全量迁移到 React/Vue。
- 不重写数据库 schema。
- 不移除旧 API 或旧 Tab。
- 不实现游戏动作执行、发包、自动化战斗或绕过安全控制。
