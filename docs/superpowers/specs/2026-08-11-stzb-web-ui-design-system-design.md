# STZB Watcher Web UI Design System

日期：2026-08-11
状态：视觉方向已确认，待后续实施
目标端：桌面 Web，兼容平板与移动端只读浏览

## 1. 设计目标

本设计系统用于统一 STZB Watcher Web 端的战场总览、实时战报、行军监控、排行中心及相关业务页面。

视觉方向来自已确认的 UI Design System 规范板：深蓝数据终端、克制的蓝紫高光、高密度信息布局、细描边面板和清晰的语义状态色。它应当体现“实时战场指挥台”，而不是传统后台管理系统，也不使用过度古风装饰。

设计需要同时满足以下目标：

- 在单屏内承载较多战报、排行和实时状态，同时保持可扫描性；
- 让连接、解析、入库、异常等运行状态一眼可辨；
- 用一致的组件和 token 降低不同 Tab 之间的视觉割裂；
- 所有重要状态均通过颜色、图标和文字共同表达；
- 保持原生 HTML + Vanilla JS + Flask 静态托管的实施可行性；
- 支持 375、768、1024、1440 和 1920 像素宽度。

## 2. 设计原则

### 2.1 数据优先

页面先呈现结论和状态，再呈现解释和原始数据。KPI、结果、排行、坐标和时间戳需要比辅助描述更醒目。

### 2.2 高密度但不拥挤

密度来自紧凑网格、稳定的列宽和分层排版，不来自缩小字体。正文不得小于 12px，核心操作和主要数据不得小于 14px。

### 2.3 深色但不纯黑

使用深海军蓝作为底色，通过多级表面色建立层次。禁止大面积纯黑、强霓虹、重度玻璃模糊和高饱和渐变背景。

### 2.4 状态必须可解释

绿色、黄色、红色和蓝色不能单独承担语义。每个状态必须同时包含图标、文字或形状标记。

### 2.5 克制的战术气质

率土主题通过盾牌、旗帜、地图、山形和阵营符号体现。禁止卷轴边框、龙纹铺底、仿木纹和过度金色装饰。

## 3. 信息架构

桌面端采用固定左侧导航、中央业务区和可选右侧情报区。

```text
┌──────────────┬────────────────────────────────────┬──────────────────┐
│ 品牌与导航   │ 页面标题 / 筛选 / 核心业务内容      │ 实时态势 / 告警   │
│              │                                    │                  │
│ 战场总览     │ KPI / 图表 / 战报表格 / 排行        │ 链路状态          │
│ 实时战报     │                                    │ 最新事件          │
│ 行军监控     │                                    │ 快捷操作          │
│ 排行中心     │                                    │                  │
│ 城池地图     │                                    │                  │
│ 团数据       │                                    │                  │
│ 攻城考勤     │                                    │                  │
│ 系统设置     │                                    │                  │
└──────────────┴────────────────────────────────────┴──────────────────┘
```

### 3.1 主导航

主导航建议顺序：

1. 战场总览
2. 实时战报
3. 行军监控
4. 排行中心
5. 城池地图
6. 团数据
7. 攻城考勤
8. 系统设置

左侧导航宽度为 208px。选中项使用蓝色半透明背景、2px 内描边和右侧短高亮线；未选中项保持低对比，不使用大面积填充。

### 3.2 页面头部

页面头部包含：

- 页面标题与一句解释；
- 当前区服、赛季或数据范围；
- 连接状态；
- 更新时间；
- 页面级操作，如刷新、暂停、导出或筛选。

头部高度控制在 72–88px，不使用巨型 Hero。

### 3.3 右侧情报区

右侧情报区只在总览、实时监控和战场告警等需要持续状态的页面出现，建议宽度 300–340px。

当视口小于 1280px 时，右侧情报区移动到主内容下方；小于 768px 时变为可展开抽屉。

## 4. 色彩系统

所有颜色必须通过语义变量使用，业务组件内禁止直接书写十六进制颜色。

### 4.1 基础色

| Token | Hex | 用途 |
|---|---:|---|
| `--bg-canvas` | `#080D22` | 页面最底层背景 |
| `--bg-sidebar` | `#0A1028` | 侧边导航 |
| `--surface-1` | `#0C1430` | 一级面板 |
| `--surface-2` | `#121D3F` | 卡片、表格和控件 |
| `--surface-3` | `#19284F` | hover、选中和凸起面 |
| `--surface-4` | `#243967` | 强调表面和禁用轨道 |
| `--border-subtle` | `#24365F` | 常规分隔线 |
| `--border-strong` | `#365080` | 聚焦与强分隔 |

### 4.2 文本色

| Token | Hex | 用途 |
|---|---:|---|
| `--text-primary` | `#F4F7FF` | 标题、正文和关键值 |
| `--text-secondary` | `#9AABCA` | 辅助描述和表头 |
| `--text-tertiary` | `#7183A7` | 次级时间、占位和禁用文本 |
| `--text-inverse` | `#061127` | 明亮按钮上的文字 |

### 4.3 品牌与状态色

| Token | Hex | 用途 |
|---|---:|---|
| `--primary` | `#38BDF8` | 主操作、链接和选中状态 |
| `--primary-strong` | `#2F80FF` | 主按钮渐变起点 |
| `--success` | `#34D399` | 在线、胜利、正常 |
| `--warning` | `#F5B84B` | 警告、等待、攻占 |

### 4.4 渐变

渐变只用于主按钮、活动进度和少量强调数值：

```css
--gradient-primary: linear-gradient(90deg, #2F80FF 0%, #38BDF8 55%, #34D399 100%);
--gradient-intensity: linear-gradient(90deg, #38BDF8 0%, #8B6CFF 48%, #F5B84B 100%);
```

禁止将渐变用于所有卡片背景。

## 5. 字体系统

### 5.1 字体栈

```css
--font-sans: Inter, "PingFang SC", "Microsoft YaHei", system-ui, sans-serif;
--font-mono: "JetBrains Mono", "SFMono-Regular", Consolas, monospace;
```

中文标题与正文统一使用现代无衬线字体。数字、坐标、时间戳、ID 和百分比使用等宽字体。

### 5.2 字级

| Token | 字号 / 行高 | 字重 | 用途 |
|---|---|---:|---|
| `--type-display` | 24px / 32px | 700 | 页面主标题 |
| `--type-section` | 20px / 28px | 650 | 大区块标题 |
| `--type-card` | 16px / 24px | 600 | 卡片标题、列表主项 |
| `--type-body` | 14px / 22px | 400 | 主体内容 |
| `--type-label` | 13px / 18px | 500 | 表头、标签和控件 |
| `--type-meta` | 12px / 18px | 400 | 时间、说明和补充字段 |
| `--type-kpi` | 28px / 34px | 700 | 核心指标 |

正文长度超过两行时，行高不得低于 1.5。

| `--space-6` | 24px | 区块间距 |
| `--space-8` | 32px | 页面级间距 |

### 6.2 圆角

| Token | Value | 用途 |
|---|---:|---|
| `--radius-xs` | 4px | 进度条、微型标签 |
| `--radius-sm` | 6px | 输入框、小按钮 |

### 6.3 边框与阴影

面板主要依靠 1px 描边区分层级，不使用厚重阴影。

```css
--shadow-panel: 0 10px 28px rgba(0, 5, 22, 0.28);
--shadow-focus: 0 0 0 3px rgba(56, 189, 248, 0.24);
--shadow-primary: 0 8px 24px rgba(47, 128, 255, 0.24);
```

## 7. 核心页面

### 7.1 战场总览

总览页面按以下顺序组织：

1. 赛季、区服和实时连接状态；
2. 战场强度进度条；
3. 今日战报、活跃队伍、同盟成员、监控事件四个 KPI；
4. 近期战斗趋势折线图；
5. 最新战报列表；
6. 右侧实时链路、当前入库量和近期告警。

桌面布局建议为 12 列网格：主内容占 8–9 列，右侧情报区占 3–4 列。

### 7.2 实时战报

顶部提供：关键词搜索、结果、同盟、时间范围和地块筛选。

表格推荐列：

- 时间；
- 战场或坐标；
- 交战双方；
- 所属同盟；
- 结果；
- 武勋或兵力；
- 详情操作。

结果使用带文字的状态标签：胜利、失败、攻占、平局。表头吸顶，数字列右对齐，行 hover 不改变尺寸。

### 7.3 行军监控

主体采用时间线或高密度事件列表。每条记录包含队伍、玩家、同盟、起点、终点、当前坐标、预计到达时间和状态。

页面必须提供暂停实时更新按钮。用户离开列表顶部时，新事件不得强制改变滚动位置，应显示“查看最新”提示。

### 7.4 排行中心

一级切换：玩家武勋、同盟武勋、玩家势力。

前三名采用紧凑领奖台，其余排行使用表格。所有图表必须保留数值标签；排行数据按降序排列，不能只靠柱状长度表达。

### 7.5 设置

设置页面采用单列分组列表，支持自动刷新、实时告警、紧凑模式、数据保留期限和隐私设置。

开关必须有明确标签和辅助描述，不能只显示开关控件。

## 8. 组件规范

### 8.1 面板

```css
.panel {
  background: var(--surface-1);
  border: 1px solid var(--border-subtle);
  border-radius: var(--radius-lg);
  box-shadow: var(--shadow-panel);
}
```

面板标题区高度建议 48px，正文区使用 16–20px 内边距。

### 8.2 KPI 卡

KPI 卡包含图标、标签、主数值和变化趋势。卡片最小宽度 160px，主数值至少 24px。

趋势必须同时显示方向图标、正负号和百分比，不能只使用绿色或红色。

### 8.3 战报行

战报行采用固定层级：

1. 选择框或结果图标；
2. 交战双方；
3. 同盟标签；
4. 坐标；
5. 时间；
6. 结果；
7. 详情箭头。

主信息保持单行，辅助信息最多两行。完整行点击区域不小于 44px 高。

### 8.4 按钮

| 类型 | 背景 | 边框 | 文字 | 用途 |
|---|---|---|---|---|
| Primary | `--gradient-primary` | 无 | `--text-inverse` | 页面主行动 |
| Secondary | `--surface-2` | `--border-strong` | `--text-primary` | 次级行动 |
| Destructive | `--danger` | 无 | 白色 | 删除、清空和危险操作 |
| Ghost | 透明 | 透明 | `--text-secondary` | 工具栏和轻量操作 |
| Disabled | `--surface-4` | 无 | `--text-tertiary` | 不可用状态 |

按钮最小高度 40px，图标按钮点击区域不小于 44×44px。

### 8.5 输入与筛选

输入框必须有可见标签，不能只使用 placeholder。聚焦时使用 2px 蓝色描边和外层 focus ring。

已应用筛选以可关闭标签展示，并提供“清除全部”。复杂筛选使用下拉面板或右侧抽屉，不在列表顶部永久占用过多高度。

### 8.6 状态标签

状态标签统一包含小型图标或形状、状态文字和语义颜色。

推荐状态：

- 正常 / 在线 / 胜利；
- 等待 / 警告 / 攻占；
- 异常 / 失败 / 高风险；
- 信息 / 已完成；
- 特殊 / 保护。

### 8.7 图标

采用 Lucide 或同类 1.5–2px 描边 SVG 图标。导航层统一 outline，当前选中项允许使用 filled 背板但不更换图标风格。

禁止 Emoji、混用多套图标和把文本符号当作正式图标。

## 9. 数据可视化

### 9.1 战斗趋势

使用折线图或面积折线图。异常点使用形状标记和文字注释，不只改变颜色。

### 9.2 排行比较

类别少于 15 个时使用水平柱状图；超过 15 个时默认使用可搜索表格。柱状图按数值降序排列，并始终显示数值。

### 9.3 战场强度

使用 bullet/progress 形式，显示当前百分比、低/中/高区间和目标标记。渐变只用于填充条。

### 9.4 实时数据

实时图表必须有暂停/继续控制，并显示当前值。开启 `prefers-reduced-motion` 后冻结流动动画，但继续更新文本值。

## 10. 页面状态

每个核心页面必须具备以下状态：

### 10.1 首次加载

使用与最终布局一致的骨架屏，避免内容载入后发生大幅位移。

### 10.2 刷新中

保留已有内容，只在标题区或局部显示进度，不清空页面。

### 10.3 空状态

空状态包含：清晰标题、原因说明和一个可执行动作，例如“清除筛选”“刷新数据”或“开启抓包”。

### 10.4 错误状态

错误信息显示在相关面板内，提供重试操作。非阻断错误不使用连续 Toast 或全屏弹窗。

### 10.5 禁用状态

禁用控件降低对比度并取消点击行为，同时保留足够可读性。禁止让禁用按钮看起来仍可点击。

## 11. 交互与动效

- hover、focus 和 pressed 过渡时间为 150–250ms；
- 不使用会改变布局尺寸的 scale hover；
- 新战报和新监控事件允许一次 200–300ms 淡入高亮；
- 弹层进入使用 ease-out，退出使用 ease-in；
- 实时状态灯可以使用 2 秒低强度脉冲；
- `prefers-reduced-motion: reduce` 下关闭位移、脉冲和装饰动画；
- 所有交互必须支持键盘，并提供清晰的 `:focus-visible` 状态。

## 12. 响应式规则

### 12.1 1440px 及以上

- 左侧导航固定；
- 中央主内容与右侧情报区并列；
- KPI 使用四列；
- 战报使用完整表格。

### 12.2 1024–1439px

- 左侧导航缩窄为图标加短标签；
- 右侧情报区移动到主内容下方；
- KPI 使用两到四列自适应。

### 12.3 768–1023px

- 左侧导航折叠为顶部或抽屉导航；
- 表格隐藏低优先级列；
- 筛选进入抽屉；
- 图表与列表单列排列。

### 12.4 375–767px

- 页面采用单列；
- KPI 使用两列；
- 战报表格转换为卡片列表；
- 固定操作不得遮挡内容；
- 不允许页面级横向滚动。

## 13. 可访问性

- 正文文本对比度不低于 4.5:1；
- 大型文字与主要图标对比度不低于 3:1；
- 所有图标按钮提供 `aria-label`；
- 表格使用正确的 `table`、`thead`、`th` 和 `scope`；
- 实时更新区域使用克制的 `aria-live="polite"`；
- 可点击区域桌面端不小于 40px，移动端不小于 44px；
- 键盘焦点顺序与视觉顺序一致；
- 状态不只依赖颜色；
- 浏览器缩放至 200% 时仍能完成主要操作。

## 14. 当前技术栈实施约束

项目当前采用 Flask 静态托管、原生 HTML 和 Vanilla JS，因此实施时遵循：

- CSS token 统一定义在 `:root`；
- 使用语义类名，不在 JS 内拼接大段内联样式；
- 图标使用内联 SVG sprite，避免多套外部图标依赖；
- 页面切换沿用现有 Tab 机制，先替换视觉壳和公共组件；
- 图表优先复用现有能力；新增图表时选择轻量 SVG/Canvas 实现；
- 避免一次性重写全部业务逻辑；
- 先改公共 token、导航、面板、表格、按钮，再逐页迁移。

## 15. 推荐实施顺序

1. 建立 CSS token 与基础字体；
2. 重做页面背景、左侧导航和面板；
3. 统一按钮、输入框、标签和状态；
4. 重做战场总览；
5. 重做实时战报和筛选；
6. 重做行军监控；
7. 重做排行中心；
8. 补齐加载、空、错误和禁用状态；
9. 完成响应式与键盘操作；
10. 执行多尺寸和对比度验收。

## 16. 验收清单

- [ ] 页面整体符合深蓝数据终端视觉，不出现浅色后台风格；
- [ ] 所有核心颜色均通过语义 token 使用；
- [ ] 导航、按钮和图标风格一致；
- [ ] 战场总览在 1440px 宽度下一屏可看到 KPI、趋势、战报和实时态势；
- [ ] 实时战报支持搜索、筛选、表头吸顶和结果状态；
- [ ] 行军监控提供暂停更新并保留滚动位置；
- [ ] 排行前三名与普通排名层级清晰；
- [ ] 所有核心页面包含加载、刷新、空、错误状态；
- [ ] 状态不只依赖颜色；
- [ ] 所有可点击元素有 hover、pressed 和 focus-visible；
- [ ] 支持 `prefers-reduced-motion`；
- [ ] 375、768、1024、1440 和 1920px 下无页面级横向滚动；
- [ ] 浏览器放大至 200% 时主要操作仍可完成；
- [ ] 现有数据查询和业务逻辑不因视觉改造发生变化。

## 17. 非目标

本设计文档不包含以下内容：

- 后端接口、数据库和抓包协议修改；
- 完整品牌 Logo 设计；
- 复杂 3D 地图或游戏场景；
- 页面文案的最终运营版本；
- 为视觉效果引入大型前端框架；
- 直接替换现有生产页面。
