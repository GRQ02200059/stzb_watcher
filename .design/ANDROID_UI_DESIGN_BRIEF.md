# Android App UI 设计交接文档

本文档面向不了解代码的 UI 设计师/设计 AI。它描述 App 的每个页面有哪些信息、如何组织、有哪些交互和状态。你只需依据本文档即可设计界面，无需阅读源代码。

---

## 一、App 概述

这是一款《率土之滨》游戏的**本机数据监控与分析工具**。安卓端通过本机 VPN 抓包解析游戏协议，把战报、同盟、排行、地图、部队等数据存到本机数据库，再以多个页面展示和分析。

**用户场景**：玩家在手机上启动抓包后切换到游戏，数据自动入库；回到本 App 查看实时战场、历史战报、同盟成员、部队动向、攻城考勤、战术模拟等。

**关键认知**：

- 数据全部来自用户自己设备的抓包，没有服务端业务数据（登录校验除外）。
- 多数页面是"本机数据库快照"，通过刷新按钮重新加载。
- 三个页面是实时的：实时战场、实时部队、抓包启动台。
- 登录页只在首次启动或会话失效时出现。

## 二、视觉基调

### 整体风格

浅色"液态玻璃"（Liquid Glass）方向：

- 背景：浅雾白到淡蓝的纵向渐变，叠加蓝/紫/青/桃四色径向环境光斑。
- 卡片：半透明白色玻璃表面，白色高光描边，柔和阴影。
- 主色：靛蓝 `#426AD2`；强调色：青绿 `#25A88E`。
- 文字：深蓝灰 `#14223A` 主文字，`#60708B` 次要文字。
- 圆角大：主卡片 20–28dp，小卡片 12–16dp，胶囊 999dp。
- 无 emoji，使用 Material 图标或自绘 SVG。

### 色彩语义

| 语义 | 颜色 | 用途 |
|------|------|------|
| 成功/运行 | 绿 `#1E9B83` | 抓包运行中、胜利、新鲜数据 |
| 警告 | 橙 `#BE7A18` | 数据老化、重要事件、集结 |
| 错误/紧急 | 红 `#C75862` | 抓包失败、失败、紧急事件、过期 |
| 信息 | 蓝 `#4C78C8` | 普通信息、战斗事件 |
| 主色 | 靛蓝 `#426AD2` | 选中态、按钮、链接 |

### 字号梯度

- 大标题 24sp / 粗体（页面标题）
- 卡片标题 18sp / 半粗（区块标题）
- 正文 16sp / 常规
- 次要正文 14sp
- 标签/胶囊 14sp / 半粗
- 辅助说明 12sp

### 导航

底部悬浮玻璃胶囊 Tab 栏，四个一级页：

1. **战场**（雷达图标）— 实时战场
2. **战报**（收据图标）— 本机战报
3. **同盟**（人群图标）— 同盟中心
4. **工具**（三点图标）— 工具中心（聚合所有二级功能）

模拟器页面（战术演练/战斗日志）会隐藏底部 Tab 栏以全屏展示。

## 三、全局设计模式

### 1. 页面标题栏 MacGlassHeader

每个页面顶部都有一个玻璃大卡片：

- 左侧大标题（24sp 粗体）
- 下方一行副标题（灰色 14sp，显示统计摘要或说明）
- 可选：左侧返回图标按钮、右侧操作按钮（刷新、导出等）

### 2. 分区标签 SectionLabel

页面内多个区块时使用：一根 3×14dp 的蓝色竖条 + 14sp 灰色半粗文字。

### 3. 卡片层级

- **一级玻璃卡** GlassCard：内容主容器，内边距 14–16dp
- **二级玻璃卡** GlassSection / 内嵌卡片：更透明、圆角 14dp，用于卡内分组
- **列表行卡**：每张卡片一个条目，卡片间距 8–10dp

### 4. 筛选条

横向可滚动的胶囊 Chip 行，选中态为浅蓝底蓝字，未选中为玻璃白底灰字。

### 5. 数据状态

每个数据页都有三态：

- **加载中**：居中旋转指示器
- **空状态**：居中收件箱图标 + 灰色说明文字 + 可选操作按钮
- **错误状态**：居中云离线图标 + 红色错误文字 + 重试按钮

实时页面还可能有：

- **暂停/缓冲**：暂停时新数据累积，显示"查看 N 条新动态"按钮
- **数据老化**：实时部队数据超过 2 分钟标记为"老化"，超过 10 分钟标记为"过期"

### 6. 列表行通用结构

大多数列表条目卡遵循：

- 顶部：标题（粗体）+ 右侧状态胶囊或时间
- 中部：摘要正文
- 底部：三列关键数据（标签 + 数值），数值用等宽数字

## 四、页面逐一说明

共 18 个页面（含 4 个一级 Tab + 二级页 + 详情页 + 登录页）。

---

### 页面 1：登录页（首次/会话失效）

**用途**：用户名+密码登录或注册，完全免费、禁止倒卖。

**结构**：

- 顶部：App 名称 + 标语
- 中部：用户名输入框、密码输入框
- 主按钮："登录" / "注册"（根据模式切换）
- 底部切换："没有账号？注册" / "已有账号？登录"
- 免费声明："本工具完全免费，禁止倒卖"
- 可选：服务公告文字、GitHub star/fork 提示

**状态**：

- 启动校验中：全屏加载
- 登录中：按钮显示"正在登录…"且不可点
- 注册中：按钮显示"正在注册…"
- 账号被封停：红色提示面板
- 服务不可用：提示 + 重试按钮
- 错误：输入框下方或顶部红色错误文字

**字段**：用户名、密码（明文传输，不做加密）。

---

### 页面 2：实时战场（一级 Tab）

**用途**：抓包运行时实时展示全服战场事件流，是 App 的核心首页。

**区块（从上到下）**：

1. **抓包状态卡**
   - 左侧：脉冲绿点 + "抓包运行中"/红点"抓包未启动"
   - 右侧："开启悬浮/关闭悬浮"按钮 + 暂停/继续图标按钮
   - 可选警告文字（红色）

2. **四个指标卡（2×2 网格）**
   - 正在行军（数值 + "N 支即将到达"）
   - 即将到达（数值 + "请留意行军变化"）
   - 今日战斗（数值 + "今日已捕获战报"）
   - 攻城动态（数值 + "城池相关事件"）

3. **分类筛选条**（横向滚动 Chip）
   - 全部、紧急、战斗、行军、攻城、系统

4. **新动态提示**（暂停时出现）
   - 居中胶囊按钮："查看 N 条新动态"

5. **事件流列表**（时间倒序）
   两种卡片样式：

   **普通事件卡**：
   - 左侧：分类图标底板（语义色淡底 + 彩色图标）
   - 标题（粗体）+ 右上角时间（HH:mm:ss）
   - 摘要文字（灰色）
   - 详情行（多行小字）
   - 底部：优先级胶囊（普通/重要/紧急）

   **行军队伍卡**（当事件包含队伍信息时）：
   - 顶部：标题 + 时间
   - 路线文字 + 两个胶囊（状态、士气）
   - 三名武将横排（位置标签 + 头像 + 名字 + 等级/进阶 + 战法 chip）
   - 底部：战绩文字 + 抵达倒计时（强调色）

**交互**：点击事件卡进入事件详情；切换分类筛选；暂停/继续；悬浮窗开关；点击"查看新动态"滚到底部。

**数据时效**：实时推送，约秒级更新。

---

### 页面 3：战场事件详情

**用途**：单条事件的完整信息。

**区块**：

1. **标题栏**："事件详情"，副标题为事件分类中文名
2. **主卡**：事件标题 + 优先级胶囊 + 摘要 + 完整时间（yyyy-MM-dd HH:mm:ss）
3. **事件信息卡**（可选）：分区标签 + 逐行详情文字
4. **关联目标卡**：
   - 战报 → "战报 #ID" + "查看完整战报"主按钮（跳转到战报详情）
   - 队伍 → "队伍 #ID"
   - 地块 → "地块 X,Y"
   - 诊断/无 → 对应文字

**空态**："该事件已被刷新，请返回战场重新选择。"

---

### 页面 4：本机战报（一级 Tab）

**用途**：浏览历史完整战报列表。

**区块**：

1. **标题栏**："本机战报"，副标题"共 N 条"，右侧刷新按钮
2. **筛选卡**：
   - 搜索框（"搜索玩家"）
   - 横向 Chip：全部、胜利、失败、攻城
3. **战报列表**

   每张战报卡：
   - 顶部：胜负胶囊（绿/红/蓝）+ 时间（MM-dd HH:mm）
   - 战报标题（粗体）
   - 地点与类型（灰色小字）
   - 三列数据：武勋（强调）、攻方兵力、守方兵力
   - 参战武将名（灰色，最多两行，用 · 分隔）

**交互**：搜索、Chip 筛选、点击进入战报详情、刷新。

**数据时效**：本机数据库缓存。

---

### 页面 5：战报详情

**用途**：单场战报的攻守双方详情。

**区块**：

1. **标题栏**：战报标题，副标题地点类型
2. **顶部两列小卡**：
   - 胜负结果 + 武勋
   - 天气码 + 昼战/夜战
3. **攻方卡**：
   - 顶部："攻方"标签（蓝色）+ 阵营名
   - 玩家名（粗体）
   - 同盟名（可空）
   - 三列：势力、武勋、兵力
   - 武将列表（每个武将一个内嵌卡）：
     - 武将名（半粗）
     - Lv.N · 进阶N · 兵力 剩余/最大
4. **守方卡**：同上结构

### 页面 6：同盟中心（一级 Tab）

**用途**：浏览同盟成员、分组、势力和贡献。

**区块**：

1. **标题栏**："同盟中心"，副标题"成员 N · 分组 N"
2. **筛选卡**：
   - 搜索框（"搜索成员"）
   - 分组 Chip（全部 + 各分组名）
3. **成员列表**

   每张成员卡：
   - 顶部：圆形头像（名字首字，浅蓝底）+ 名字（粗体）+ 分组名（蓝色小字）
   - 右上角：职位胶囊（数字职位码，0 显示"成员"）
   - 三列数据：势力（强调）、武勋、周贡献
   - 底部：UID（灰色小字）

**数据时效**：本机数据库缓存。

### 页面 7：工具中心（一级 Tab）

**用途**：所有二级功能的聚合入口。

**区块（分组 + 3 列磁贴网格）**：

1. **战斗与队伍**

   - 实时部队、地图城池、游戏公告
   - 排行榜、（两个空位保持对齐）

3. **抓包与经典**
   - 抓包启动台、经典数据页面、（空位）

4. **账号**
   - 账号与区服、退出登录、（空位）

**磁贴样式**：40dp 圆角方块图标（浅蓝底）+ 下方中文标签。

### 页面 8：抓包启动台

**用途**：控制本机 VPN 抓包，查看状态和证据链。

**区块**：

1. **标题栏**："抓包启动台"，副标题"本机 VPN → SOCKS5 → STZB 协议解析"
2. **抓包状态卡**
   - 左："抓包运行中/未启动"（粗体）
   - 右："N 包"（蓝色粗体）
   - SOCKS 地址（灰色小字）
   - native 组件缺失时红色提示
3. **真实抓包闭环卡**（证据链）
   - 标题 + 当前进度（"六阶段验证通过"或"下一步：XXX"）
   - 六行清单，每行：
     - 阶段名（Native 组件 / VPN 通道 / SOCKS 连接 / 已知协议 / 本地入库 / 停止与网络恢复）
     - 右侧"已通过"（绿）或"待验证"（灰）
   - 未完成时显示长说明文字
4. **抓包控制卡**
   - 只读输入框显示目标 App（显示名+包名）
   - "搜索并选择 App"按钮
   - 两按钮并排："启动抓包"（主按钮）、"停止抓包"（描边按钮）
5. **抓包日志卡**
   - 协议 ID 筛选输入框（提示"5026, 5028"）
   - 日志显示区（等宽字体，最小高度 120dp，空时"等待 STZB 业务包解析…"）
   - "清空内存日志"按钮
6. **导出卡**
   - 四个全宽按钮：导出解析包、导出数据库、导出诊断、导出抓包证据
   - "打开旧控制台"文字按钮
7. 瞬时消息（蓝色或红色文字）

**交互**：启动时会弹系统 VPN 授权对话框；选择 App 弹出搜索对话框。

**数据时效**：实时运行状态。

### 页面 9：排行榜

**用途**：战功榜、同盟势力榜、个人势力榜。

**区块**：

1. **标题栏**："排行与团队报表"，副标题"排行榜、周期报表与团队维度"
2. **切换卡**：
   - 页面 Chip：排行榜 / 团队报表
   - 排行榜时：分类 Chip（战功榜 / 同盟势力 / 个人势力）
   - 报表时：周期 Chip + 维度 Chip + 分组 Chip
3. **排行榜列表**

   每行：
   - 左：圆形名次徽章（第 1 金、第 2 银、第 3 铜，其余蓝）
   - 中：名称（粗体）+ 分组名（蓝色小字）
   - 右：主指标（蓝色粗体）
   - 战功榜额外显示："战功 N · N 场 · 胜率 N%"
   - 同盟势力显示："势力 N · N 人"

4. **团队报表视图**：
   - 顶部汇总卡：三项（共 N 项 / 战斗 N / 武勋 N）
   - 列表行类似排行榜，右侧显示武勋，下方显示战绩

### 页面 12：实时部队

**用途**：展示当前地图上的出征队列、路线、阵容和新鲜度。

**区块**：

1. **标题栏**："实时部队"，副标题"当前 N · 行军 N · 精确阵容 N"
2. **搜索框**（独立卡）："搜索队伍 ID、玩家、武将或 WID"
3. **部队列表**

   每张部队卡：
   - 顶部：队伍 ID + 玩家名（粗体）+ 状态胶囊（行军中为蓝底蓝字，其余灰底）
   - 同盟 · 新鲜度（灰色小字）
   - 路线文字："出发 → 当前 → 目标"
   - 三列数据：士气（强调）、阵容证据、战绩（若有）
   - 武将名（粗体，用 / 分隔）
   - "回到战场定位"全宽按钮

**新鲜度标记**：

- 新鲜（≤2 分钟，绿色）
- 老化（2–10 分钟，橙色）
- 过期（>10 分钟，红色，不可用）
- 时间未知

**阵容证据**：精确战报阵容 / 观测武将类型 / 阵容未知。

**数据时效**：实时，约 10 秒级。

### 页面 13：攻城考勤

**用途**：创建攻城任务，统计成员出勤和战斗明细。

**两个视图**：

**任务列表视图**：

1. **标题栏**："攻城考勤"，副标题"任务、成员、战报与统计"
2. **新建任务卡**：
   - 任务名输入框
   - 坐标（WID 或 X,Y）输入框
   - 目标分组（逗号分隔，留空全员）
   - 任务时间（Unix 秒，可留空）
   - "创建任务"按钮
3. **任务列表**：
   - 任务名（粗体）
   - 坐标 · 分组
   - 目标 N · 已出战 N

**任务详情视图**：

1. **标题栏**：任务名，副标题"坐标 X,Y · 目标 N · 已出战 N"，返回箭头
2. **操作行**："开始统计" + "导出 CSV" 两个等宽按钮
3. **删除任务**全宽描边按钮

## 五、设计约束与注意事项

1. **无 emoji**：所有标签和状态使用文字或 Material 图标，不要用表情符号。
2. **全中文**：所有面向用户的文字使用简体中文。
3. **数据可能为空**：任何列表都可能为空，必须设计空状态。抓包未启动时战场页就是空的。
4. **数据可能实时刷新**：战场和实时部队列表会持续追加内容，设计时考虑列表性能和新内容提示。
5. **武将头像**：使用游戏内头像资源（已缓存），无头像时用名字首字占位。
6. **等宽数字**：数值、时间、ID 使用等宽数字（tabular-nums）以避免跳动。
7. **长文本省略**：玩家名、同盟名、战法名可能很长，单行显示省略号。
8. **安全区**：底部 Tab 栏和顶部标题栏需考虑系统手势条和状态栏。
9. **横屏/平板**：当前主要面向竖屏手机，暂不需要横屏适配。
10. **免费声明**：登录页必须标注"完全免费，禁止倒卖"。
11. **可访问性**：图标按钮需有 contentDescription，最小点击区域 44dp。
