# stzb_watcher 使用文档

## 1. 软件简介

`stzb_watcher` 是《率土之滨》的 Web + Android 双端战场数据平台，主要用于：

- 采集和解析本地 STZB 网络业务数据；
- 查看战场态势、实时行军、战报和地图信息；
- 查询玩家队伍、同盟成员、团数据和攻城考勤；
- 统计武勋、势力、阵容表现和州郡分布；
- 使用战斗模拟器推演攻守双方阵容；
- 导出解析包、本地数据库、诊断信息和团队报表。

Web 端适合电脑大屏、持续监控和多区域对比；Android 端适合手机本机抓包、快速查看和移动操作。两端均以本地数据为主，不要求 Android 端连接电脑上的 Flask 服务。

> 本文是面向使用者的操作手册。开发、构建和协议迁移说明请参考 [项目 README](../README.md)、[Android 工程说明](../astzb/README.md) 和 [Android 出包指南](../astzb/BUILD_RELEASE.md)。

## 2. 最快开始

### 2.1 Android 用户：从 Releases 下载

普通用户不需要下载源码，也不需要自己编译 APK。请按以下步骤安装：

1. 打开项目的 [Releases 页面](https://github.com/GRQ02200059/stzb_watcher/releases)。
2. 进入最新版本的 Release。
3. 展开页面中的 `Assets`。
4. 点击正式安装包 `app-release.apk` 下载。
5. 下载完成后，在手机文件管理器或浏览器下载列表中点击 APK。
6. 按系统提示允许当前文件管理器或浏览器“安装未知应用”。
7. 返回安装界面，确认安装。
8. 安装完成后打开 `st助手安卓独立版`。

下载时请注意：

- 不要点击 `Source code (zip)` 或 `Source code (tar.gz)`，它们是项目源码，不是安装包；
- 不要把 `app-debug.apk` 作为正式分发包；
- 如果 Release 中同时存在 `app-release-unsigned.apk`，它是未签名包，普通用户应优先选择已签名的 `app-release.apk`；
- 如果页面存在多个 APK，选择文件名包含 `release` 且不包含 `unsigned` 的 ARM APK；
- 当前 Android 工程要求 Android 13 或更高版本，主要支持 `arm64-v8a` 和 `armeabi-v7a`。

### 2.2 Web 用户：本地启动

Windows 用户可以优先下载 Release 中的 EXE，其他用户可以通过 Python 命令启动 Web 服务。

#### Windows EXE 启动

1. 打开项目的 [Releases 页面](https://github.com/GRQ02200059/stzb_watcher/releases)。
2. 进入最新版本，展开 `Assets`。
3. 下载文件名以 `.exe` 结尾的 Windows 程序。
4. 如果下载的是压缩包，先完整解压。
5. 双击运行 EXE。
6. 如果程序没有自动打开浏览器，访问 `http://127.0.0.1:8080`。

使用过程中请保持 EXE 进程运行。关闭 EXE 后，本地 Web 服务也会停止。如果 Windows Defender 弹出安全提示，请确认下载来源是项目 Release 后再选择允许运行。

下载时不要选择 `Source code (zip)`、`Source code (tar.gz)` 或 Android 的 `.apk` 文件。Release 中存在多个 EXE 时，优先选择标注为 Windows、release 或正式版本的文件。

#### Python 启动

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

./gradlew -p battle-engine test installDist
python api_server.py
```

启动后打开：

```text
http://127.0.0.1:8080
```

如果浏览器没有自动打开，也可以手动复制这个地址。Web 服务启动时会初始化本地数据库结构、启动实时写入，并尝试启动 Web 侧数据采集。

Web 端的基本要求：

- Python 3.9 或更高版本；
- JDK 17；
- 支持现代 JavaScript、Canvas 和 SSE 的 Chrome 或 Chromium 浏览器；
- 如果需要重新构建战斗引擎，需要能够运行 Gradle 的网络或本地依赖缓存。

## 3. Android 端使用

### 3.1 首次打开

打开 App 后默认进入 `战场` 页面。底部有五个一级入口：

| 入口 | 用途 |
|---|---|
| 战场 | 查看实时事件、数据摘要、筛选和战场状态 |
| 队伍 | 查询玩家、同盟、武将和战法组成的队伍 |
| 团队 | 查看团队报表、周期统计和成员表现 |
| 模拟 | 配置双方阵容并运行战斗模拟 |
| 更多 | 战报、同盟、地图、公告、排行、抓包和经典页面入口 |

首次使用建议先进入 `更多 → 抓包启动台`，完成目标 App 选择和 VPN 授权，再回到 `战场` 查看数据。

### 3.2 启动本机抓包

Android 端的主要数据链路如下：

```text
目标游戏 App
  → Android VPN
  → 本机 SOCKS5 桥接
  → STZB 协议解析
  → 本地 SQLite
  → Android 页面展示
```

具体操作：

1. 打开 `更多 → 抓包启动台`。
2. 点击 `搜索并选择 App`。
3. 选择需要采集数据的游戏 App。
4. 确认页面显示了目标 App，并且 native 抓包组件状态正常。
5. 点击 `启动抓包`。
6. 第一次启动时，在系统弹窗中确认 VPN 权限。
7. 切换到游戏，执行登录、打开地图、查看战报、查看队伍等联网操作。
8. 返回 `st助手安卓独立版`，查看 `STZB 解析日志`。
9. 看到 `5026`、`5028`、`10`、`92` 或 `2100` 等业务消息后，回到 `战场`、`战报`、`地图与城池` 等页面查看结果。
10. 使用完毕后回到抓包启动台，点击 `停止抓包`。

抓包期间 Android VPN 可能会接管设备的网络流量。建议只在需要采集目标游戏数据时启动，使用完成后及时停止。

### 3.3 查看战场

`战场` 页面是 Android 端的实时事件 Feed，通常用于快速确认数据链路是否正常：

- 查看最近解析到的战场事件；
- 按事件类别筛选；
- 暂停或恢复事件流；
- 新事件到达时查看缓冲数量；
- 刷新本机数据；
- 在支持的设备上开启战场悬浮窗。

如果页面为空，先确认抓包正在运行，并在游戏中执行会产生网络请求的操作。

### 3.4 查看队伍与团队

`队伍` 页面支持：

- 按玩家、同盟、武将或战法搜索；
- 切换攻方、守方或全部队伍；
- 查看三名武将、位置、战法、出战次数、胜场和胜率。

`团队` 页面支持：

- 按今日、昨日、本周、上周或全部时间查看；
- 按分组或按成员查看；
- 按分组筛选成员；
- 导出当前团队报表 CSV。

队伍数据依赖已采集的完整战报。如果看到“本机还没有全服玩家队伍数据”，请先启动抓包并在游戏中打开或产生完整战报。

### 3.5 使用更多工具

进入 `更多` 后可以打开：

| 页面 | 主要用途 |
|---|---|
| 战报 | 查看完整战报，点击列表项进入战报详情 |
| 同盟成员 | 查看同盟成员及分组信息 |
| 地图与城池 | 查看 `5026` 地图格子、城池和类型统计 |
| 游戏公告 | 查看本机解析到的公告 |
| 排行榜 | 查看玩家武勋、同盟武勋和势力排行 |
| 抓包启动台 | 选择目标 App、启动/停止抓包、查看日志和导出 |
| 经典数据页面 | 打开仍由旧版 `DashboardActivity` 承载的完整数据页面 |

部分较复杂的页面仍通过“经典数据页面”进入，这是兼容入口，不代表数据需要连接 Web 服务器。

### 3.6 使用战斗模拟

进入底部 `模拟`：

1. 选择攻方和守方武将；
2. 配置等级、进阶、战法等参数；
3. 运行单场或多次模拟；
4. 查看结果摘要；
5. 打开战斗日志查看第一场事件回放。

模拟结果用于阵容研究和方案比较，不等同于真实游戏中的最终战果。

### 3.7 导出数据

在 `更多 → 抓包启动台` 的 `导出与兼容` 区域，可以导出：

- `导出解析包`：导出近期识别到的 STZB 应用层解析结果；
- `导出数据库`：导出本机 SQLite 数据库；
- `导出诊断`：导出消息计数、协议分布和近期包预览等排查信息。

点击导出后，系统会弹出文件保存位置。建议排查问题时同时保留：

1. App 版本或 Release 下载地址；
2. 导出的诊断文件；
3. 导出的解析包；
4. 必要时再提供数据库文件。

数据库和解析包可能包含角色名、同盟名、区服信息、坐标和战斗记录，请确认隐私后再分享。

## 4. Web 端使用

### 4.1 打开和确认连接状态

进入 `http://127.0.0.1:8080` 后，顶部状态栏可以看到：

- 当前连接状态；
- 战报数量；
- 武勋数量；
- 在线时间；
- 当前账号/区服档案。

首页会显示战场总览、活跃行军、最近数据和常用快捷入口。第一次打开时如果数据为空，先启动游戏数据采集，再点击页面中的刷新按钮。

### 4.2 Web 主导航

Web 端当前主要页面如下：

| 页面 | 用法 |
|---|---|
| 战场情报 | 查看态势地图、实时行军、活跃部队、协议实体和证据时间线 |
| 实时部队 | 按部队 ID、玩家、武将或 WID 搜索，查看部队状态、位置、方向和目标 |
| 玩家队伍 | 查看玩家常用阵容、攻守侧、战法和实战表现 |
| 同盟成员队伍 | 按分组查看同盟成员队伍和胜率 |
| 打城考勤 | 创建攻城任务，查看成员安排、出战战报和考勤结果 |
| 团数据 | 按周期、分组或成员汇总战斗、攻城、武勋和活跃度 |
| 自定义积分 | 管理积分规则、调整项、预览和重算赛季榜单 |
| 武将阵容 | 根据历史战报统计三人组合的出战次数、胜负和平衡胜率 |
| 阵容战法研究 | 区分配置事实、历史统计和模拟验证，追踪阵容研究证据 |
| 战斗模拟 | 配置双方阵容，运行单场或批量 Kotlin 战斗引擎模拟 |
| 州郡分布 | 按全部成员或指定团查看各州人数、势力、同盟和分组 |
| 设置中心 | 调整自动刷新、信息密度、动效、声音提醒和运行链路检查 |

### 4.3 战场情报和实时部队

建议按以下顺序使用实时功能：

1. 进入 `战场情报`，确认态势地图可以加载；
2. 切换 `实时行军`，观察当前行军和目标；
3. 进入 `实时部队`，使用搜索框按部队 ID、玩家、武将或 WID 定位；
4. 查看部队详情中的身份、阵容证据和历史战报；
5. 如果需要从实时部队回到地图定位，点击 `在战场情报中定位`。

实时数据有新鲜度概念。游戏状态变化后，页面可能需要等待下一次采集或点击刷新；不要把长时间未更新的行军信息当作当前事实。

### 4.4 战报、队伍和阵容分析

推荐的分析顺序是：

1. 在 `战场情报` 或 `实时部队` 找到目标玩家、部队或地块；
2. 打开关联的战报详情，确认时间、攻守双方、结果和 WID；
3. 在 `玩家队伍` 或 `同盟成员队伍` 查看常用阵容；
4. 在 `武将阵容` 查看三人组合的历史统计；
5. 在 `阵容战法研究` 区分历史证据和模拟验证；
6. 在 `战斗模拟` 配置候选阵容，进行对比推演。

历史胜率只代表当前本地数据库中的样本，样本数量不足时不要把统计结果直接视为强结论。

### 4.5 创建攻城考勤任务

在 `打城考勤` 页面：

1. 点击 `新建任务`；
2. 填写任务名称；
3. 输入城池坐标，可以使用 WID 或坐标格式；
4. 设置任务时间；
5. 选择按分组选人，或使用按距离智能分配；
6. 确认目标成员后创建任务；
7. 打开任务详情，查看概览、成员、战报和操作信息；
8. 点击任务统计，生成成员出战考勤；
9. 需要分享时导出 CSV。

考勤统计依赖对应时间范围内已采集的战报。任务创建后如果还没有关联战报，需要等待采集或手动刷新。

### 4.6 团数据和自定义积分

`团数据`支持：

- 今日、昨日、本周、上周和全部周期；
- 按分组或按成员查看；
- 按指定分组筛选；
- 查看战斗、攻城、胜负、武勋和成员数量；
- 导出 PDF 或长图，具体以当前页面显示的导出按钮为准。

`自定义积分`适合有自定义赛季规则的团队：

1. 先配置积分规则；
2. 通过预览确认规则对当前数据的影响；
3. 必要时添加成员调整项；
4. 激活需要使用的规则；
5. 执行重算并查看榜单。

积分规则、调整和重算属于写操作；如果服务端配置了 `STZB_API_TOKEN`，浏览器需要在 `设置中心` 填写当前会话的写操作 Token。

### 4.7 设置中心

设置中心中的偏好只保存在当前浏览器，不会直接修改游戏或数据库。主要选项包括：

- 自动刷新：关闭、5 秒、10 秒或 30 秒；
- 信息密度：舒适或紧凑；
- 界面动效：完整、标准或精简；
- 声音提醒：关闭、仅危险或全部；
- 右侧情报栏：控制总览中的战术预警；
- 写操作 Token：仅保存在当前浏览器会话。

如果页面显示运行链路异常，先点击 `刷新`，再检查 Web 服务进程、数据库文件和采集线程。

### 4.8 切换账号或区服档案

如果项目中存在多个本地档案，顶部账号下拉框可以切换角色和区服：

1. 点击顶部账号下拉框；
2. 选择目标角色/区服；
3. 等待页面自动刷新；
4. 确认顶部摘要和数据数量已经切换。

切换档案会改变当前 Web 查询所使用的本地数据库。不要在数据写入过程中频繁切换，避免把不同档案的数据混淆。

## 5. Web 安全和局域网访问

默认建议只在本机访问 `127.0.0.1`。如果确实需要让局域网设备访问，应设置写操作 Token：

```bash
export STZB_API_TOKEN='请替换为随机长字符串'
python api_server.py
```

配置 Token 后，以下类型的操作需要授权：

- 切换档案；
- 刷新或同步数据；
- 创建、删除和统计攻城任务；
- 创建、激活、调整和重算自定义积分；
- 其他会改变本地数据或运行状态的写操作。

不要把 Token、数据库、抓包文件、角色信息或发布签名文件提交到公开仓库。

## 6. 常见问题

### 6.1 Android 安装失败

按错误类型处理：

| 现象 | 处理 |
|---|---|
| 找不到安装包 | 回到 Release 的 `Assets`，下载 `.apk`，不要下载源码压缩包 |
| `INSTALL_PARSE_FAILED_NO_CERTIFICATES` | 检查是否下载了 `app-release-unsigned.apk`，改用已签名的正式包 |
| `INSTALL_FAILED_UPDATE_INCOMPATIBLE` | 卸载设备上的旧签名版本，再安装当前 Release |
| `INSTALL_FAILED_VERSION_DOWNGRADE` | 当前版本号低于已安装版本，卸载旧版或使用更高版本 Release |
| 系统版本不满足 | 当前工程最低 Android 版本为 Android 13 |
| ABI 不匹配 | 当前正式包面向 ARM 设备，优先使用 `arm64-v8a` 或 `armeabi-v7a` 设备 |

### 6.2 Android 能打开但没有数据

按顺序检查：

1. 是否进入了 `更多 → 抓包启动台`；
2. 是否选择了正确的目标游戏 App；
3. 是否点击了 `启动抓包`；
4. 是否完成系统 VPN 授权；
5. 是否切回游戏执行了登录、开地图或打开战报等联网操作；
6. 是否在解析日志中看到 `5026`、`5028`、`10`、`92` 或 `2100`；
7. 是否点击了页面刷新；
8. 是否在使用完毕后误点了 `停止抓包`。

HTTPS 流量不会因为 VPN 或 tun2socks 自动解密；当前能力依赖能够被本机协议链路识别的 STZB 数据。

### 6.3 Web 页面打不开

先确认启动命令没有报错：

```bash
python api_server.py
```

然后检查：

```bash
curl http://127.0.0.1:8080/
curl http://127.0.0.1:8080/api/status
```

如果端口被占用，先关闭旧的 `api_server.py` 进程，再重新启动。若依赖安装失败，确认虚拟环境已激活，并重新执行 `pip install -r requirements.txt`。

### 6.4 Web 页面有界面但数据为空

空数据通常表示本地还没有对应业务数据，而不是页面故障。建议：

1. 确认 `api_server.py` 已启动采集线程；
2. 确认游戏正在进行联网操作；
3. 等待实时写入完成；
4. 点击当前页面的 `刷新`；
5. 在 `设置中心` 查看运行链路；
6. 在战场情报页确认数据新鲜度。

不同页面依赖不同消息类型。例如地图和城池依赖地图数据，实时部队依赖行军数据，阵容和队伍依赖战报数据。

### 6.5 Web 写操作返回未授权

如果返回“写操作需要有效的 STZB API Token”：

1. 确认启动服务时设置了 `STZB_API_TOKEN`；
2. 打开 `设置中心`；
3. 在 `写操作 Token` 中填写完全相同的值；
4. 重新执行操作。

如果只是查看数据，通常不需要 Token。

### 6.6 数据看起来过期

实时部队、地图和世界态势都依赖最近一次采集。请先点击刷新，并确认游戏仍在运行。如果状态持续不更新，优先检查采集线程、目标 App/VPN 状态和本地数据库更新时间。

## 7. 数据与隐私

项目默认采用本地优先策略：

- Web 原始采集数据写入项目目录下的 `capture_new/`；
- Web 业务数据保存到本地 SQLite；
- Android 数据保存在 App 私有目录的本地 SQLite；
- 导出文件可能包含角色名、同盟、区服、坐标、战报和原始报文摘要；
- `current_profile.json`、`profiles.json` 可能包含角色和本机路径；
- 对外分享截图、数据库或解析包前，应先检查并遮挡账号信息。

请只在获得授权的设备、账号和网络环境中使用抓包与数据采集能力，并遵守游戏服务条款及适用的数据隐私要求。
